## 2. 서비스 경계 — 왜 세 언어로 나누나
세 언어를 쓰면 실행할 런타임이 셋이 된다. 그래서 **각 언어가 가장 잘하는 도메인을 하나씩** 맡기고, 서비스끼리는 HTTP + 계약 스키마로만 통신한다. 모든 서비스를 한 명령으로 띄운다(§7).

| 서비스 | 언어 | 맡는 것 | 맡지 않는 것 | 자기 저장소 |
|---|---|---|---|---|
| gateway | TS | 웹의 유일한 창구, AI 에이전트(워크플로·의도·설명·초안 서술), SSE, 세션·트레이스, 다른 서비스 호출 | 예측 계산, 문서 파일 생성, 영구 업무 기록 | `data/app/gateway.sqlite`, `traces/` |
| forecast | Python | 데이터 수집·가공, 라벨, 피처, 모델 학습·백테스트, 예측·판정, 유사 행사, 평시 방문, 일괄 예보, 인사이트, 사전 등록 선정·채점, 파이프라인(B) | 사용자 대화, 문서 편집 | `data/processed/*.parquet`, `data/cache/`, `models/`, `reports/backtest/` |
| records | PHP | 내 행사 CRUD, 예보 스냅샷(불변), 계획 초안 CRUD·**docx 내보내기**, **사전 등록 원장**(해시 체인, 검증), 실측 입력, 공유 링크 | 예측 계산, LLM 호출 | `data/app/records.sqlite` |
| web | React | 화면, 상호작용, 지도·차트 | 비즈니스 계산(숫자는 API JSON 그대로 표시) | 브라우저 저장소(필터 기억 정도) |

- **데이터 소유 원칙**: 각 저장소는 소유 서비스만 쓴다. 다른 서비스의 DB 파일을 직접 열지 않는다.
- **숫자 원칙**: 예측·판정 숫자는 forecast만 만든다. gateway의 LLM과 web은 숫자를 받아 표시·설명만 한다.

## 3. AI 에이전트 (로컬 LLM에 맞춘 설계)

### 3-1. 스모크 테스트 결과 (9/24, Ollama 0.34.1)
| 모델 | JSON 스키마 강제 추출 | 자유 도구 호출 |
|---|---|---|
| `qwen3:4b-instruct-2507-q4_K_M`(설치됨) | **1.5초**, 유형·날짜·야간·인천 중구·무료 정확, `missing` 판단만 틀림 | 연도 2023, 시군구 "영종", 유형 enum 이탈 |
| `qwen2.5:7b`(설치됨) | 6.1초, 시군구 "중구"(시도 누락) | 날짜 "10월 18일" 원문 그대로 |

→ **결론**: 작은 로컬 모델에게 도구 인자를 맡기지 않는다. LLM은 ① 스키마 강제 **추출** ② 스키마 강제 **의도 분류** ③ **설명·서술 생성**만 하고, 정규화·누락 판단·도구 실행은 코드가 한다.

### 3-2. 모델 선택 (T-302에서 측정 후 확정)
- 후보: `qwen3:4b-instruct-2507`(설치됨, 빠름), `qwen2.5:7b`(설치됨), `qwen3:8b`(받아야 함, 약 5GB로 8GB VRAM에 들어감).
- 평가 세트: 한국어 행사 문장 30개(`services/gateway/evals/extract_cases.jsonl`) → 필드 정확도, 모호성 탐지, 설명 문장 품질(숫자 자리표시자 준수율), 지연.
- 역할별 모델: `OLLAMA_MODEL_FAST`(추출·의도, 기본 4b), `OLLAMA_MODEL_WRITE`(설명·초안 서술, 평가로 결정).
- 발표 노트북에 GPU가 없을 때를 대비해 4b를 기본으로 두고, 데모 재생 모드를 준비한다.

### 3-3. 기본 흐름 = 코드가 정한 워크플로 (`services/gateway/src/agent/steps/`)
| 단계 | 파일 | 담당 | 하는 일 |
|---|---|---|---|
| 1 | `extract.ts` | LLM(스키마 강제) | 문장 → `EventDraft`(유형·날짜·시간대·장소·요금·홍보·주최·위험요소 단서) |
| 2 | `normalize.ts` | 코드 | 상대 날짜("둘째 주 토요일")를 오늘 기준으로 계산, 요금·시간대·유형 정규화 |
| 3 | `geocode.ts` | 코드 → forecast | 장소 → 시군구 후보. 2개 이상이면 `ask` 이벤트("인천 중구 / 서울 중구 …") |
| 4 | `completeness.ts` | 코드 | 필수값(날짜·장소·유형) 확인 → 없으면 `ask`. 선택값(예산)은 건너뛰기 가능 |
| 5 | `gather.ts` | 코드 → forecast | 평시 방문·유사 행사 병렬 조회 |
| 6 | `predict.ts` | 코드 → forecast | 예측·판정·요인·OOD → `forecast` 이벤트 |
| 7 | `explain.ts` | LLM + 코드 | 요인 JSON → 설명 문장(숫자는 `{{p50}}` 같은 자리표시자만 허용) → 코드가 채움 → 숫자 가드 |
| 8 | `suggest.ts` | 코드 | 다음 할 일 버튼(초안·재예보·저장·what-if) |

### 3-4. 후속 질문 = 의도 라우터 (`src/agent/intents/`)
- LLM이 스키마 강제로 `{intent, slots}`를 고른다: `whatif_date` · `whatif_weather` · `whatif_fee` · `whatif_time` · `explain_factor` · `compare_similar` · `make_plan` · `save_event` · `out_of_scope`.
- 의도마다 파일 하나(`intents/whatif-date.ts` 등)가 코드로 도구를 다시 실행하고, 이전 예보와의 차이를 계산해 `forecast` 이벤트로 보낸다. 설명은 3-3의 7단계를 재사용한다.

### 3-5. 계획 초안 서술 (`src/agent/plan/sections/`)
- 섹션마다 파일 하나: `overview.ts` · `organization.ts` · `crowd-timeline.ts` · `routes-evacuation.ts` · `staffing.ts` · `traffic-parking.ts` · `medical-toilets.ts` · `weather-emergency.ts` · `non-crowd-risks.ts`.
- 각 파일 = 사실 묶음(예보 JSON에서 추출) + 서술 프롬프트 + 숫자 자리표시자 → records에 저장 → PHPWord로 docx.

### 3-6. 가드레일 (`src/agent/guards/`)
| 가드 | 규칙 | 위반 시 |
|---|---|---|
| `numbers.ts` | 설명·초안에 자리표시자 밖 숫자 금지(날짜·순번 제외) | 1회 재생성 → 실패 시 템플릿 문장 |
| `phrases.ts` | 단정 표현("반드시 ~명", "확실히") 금지 | 문장 교체 |
| `ood.ts` | forecast의 OOD 플래그 | "참고용" 배지, 초안 버튼 비활성 |
| `budget.ts` | 세션당 LLM 호출 ≤ 12, 호출당 30초 제한 | 템플릿으로 대체 |
| `fallback.ts` | Ollama 연결 실패·시간 초과 | 추출 → 폼 입력으로, 설명 → 템플릿으로. **예보서는 항상 나온다** |

### 3-7. SSE 이벤트 계약 (`packages/contracts/sse-events.md`)
`step` · `tool_call` · `tool_result` · `event_card` · `ask` · `forecast` · `text_delta` · `guard` · `suggest` · `done` · `error`. 페이로드는 JSON Schema로 고정한다. 웹은 `forecast` 이벤트의 JSON만으로 예보서를 그린다.

### 3-8. 트레이스와 데모 재생
- 세션마다 `traces/{session_id}.jsonl`(단계·도구·입력 요약·출력 요약·지연·모델·가드 이벤트).
- `GET /api/agent/replay/{trace_id}`: 저장된 트레이스를 같은 SSE 이벤트로, 원래 간격대로 재생한다(발표장 장애 대비).

### 3-9. B·C 에이전트
- **B 분석 자동화**(forecast): `crowdcast pipeline run` = fetch → labels → features → train → backtest → batch → publish. 단계마다 게이트(`06` §8)를 두고, 마지막에 Ollama가 실행 요약을 쓴다(숫자는 자리표시자). 실행 기록은 `reports/runs/{run_id}/`. `scripts/nightly.sh`로 매일 03:00 실행(WSL cron 또는 Windows 작업 스케줄러).
- **C 평가**: gateway `npm run eval`(시나리오 20·추출 30), forecast `pytest -m golden`, records 계약 테스트 → `reports/evals/{date}.md`. S8 운영 화면에 표시한다.

## 5. 계약 관리 (세 언어가 한 스키마를 쓰는 방법)
- 정본: `packages/contracts/schemas/*.schema.json`(JSON Schema 2020-12). 도메인 객체: `event`, `event-draft`, `forecast`, `judgment`, `factor`, `similar-event`, `region-baseline`, `festival-summary`, `plan`, `plan-section`, `ledger-entry`, `insight`, `backtest-summary`, `sse-event`.
- OpenAPI 3.1 파일은 서비스마다 하나이고, 위 스키마를 `$ref`로 참조한다.
- 코드 생성: TS 타입(`json-schema-to-typescript`) + Ajv 런타임 검증(**2020-12는 `ajv/dist/2020`**, 기본 export는 draft-07), pydantic v2 모델(`datamodel-code-generator --output-model-type pydantic_v2.BaseModel`), PHP는 opis/json-schema로 요청·응답을 검증한다. 생성 도구 버전·옵션을 고정하고 생성물은 커밋한다. `npm run contracts:gen` 재생성 후 diff가 없어야 한다.
- 공통 규칙: 모든 객체 `additionalProperties: false`, 날짜는 ISO 8601 문자열(`format: date`/`date-time`, KST), 값 없음은 `type: [..., "null"]`로 명시, 금액은 원 단위 정수, 인원은 정수.
- **먼저 검증**(T-001): 대표 계약 `forecast` 하나를 세 언어에서 로드해 같은 정상·오류 픽스처를 똑같이 판정하는지 확인한 뒤 14종으로 확장한다.
- 계약 테스트: 각 서비스의 테스트가 자기 응답을 스키마로 검증한다. 공용 픽스처는 `packages/contracts/fixtures/`.
- 계약 변경은 오케스트레이터만 한다(`AGENTS.md` 규칙 2).

## 7. 로컬 실행
### 7-1. 한 번만 (`npm run setup`)
1. Node 22·npm(설치됨), uv(설치됨) → `uv python install 3.12`
2. PHP 8.5 + Composer: `sudo apt install php-cli php-sqlite3 php-xml php-mbstring php-zip php-gd composer` (**사람이 sudo로 실행**, Ubuntu 26.04 apt 후보 8.5 확인). 완료 조건: `php -v` 8.5.x, `php -m`에 pdo_sqlite·xml·mbstring·zip·gd, `composer -V`
3. `npm install`(workspaces) · `uv sync`(forecast) · `composer install`(records)
4. `node scripts/fetch-assets.mjs`: Protomaps 한국 영역 PMTiles(bbox·maxzoom 13·빌드 날짜 고정) + **글꼴(glyph PBF)·스프라이트**, 시군구 경계(라이선스 확인 후), Pretendard → `data/external/` 저장 후 `apps/web/public/map/`에 링크(Vite 정적 제공, HTTP Range 동작은 T-403에서 확인하고 안 되면 gateway 정적 라우트로 제공)
5. Ollama 모델 확인·받기: `POST $OLLAMA_HOST/api/pull`

### 7-2. 매번 (`npm run dev`)
- `scripts/dev.mjs`가 ① `OLLAMA_HOST`를 정하고 ② 네 앱 서비스를 `concurrently`로 띄우고 ③ **앱 서비스 4개**의 health만 기다린 뒤(최대 60초) 브라우저 주소를 출력한다. **Ollama 상태는 따로 표시만 하고 기동을 막지 않는다**(꺼져 있으면 템플릿 모드로 동작).
- **WSL → Windows Ollama 접속 조건**(9/24 확인): Windows에서 Ollama가 `OLLAMA_HOST=0.0.0.0:11434`로 바인딩돼 있고(사용자 환경변수 설정됨), WSL이 NAT 모드(`.wslconfig` 네트워크 설정 없음)라 WSL 기본 게이트웨이 IP(`172.20.32.1`, 재부팅하면 바뀔 수 있음)로 접속된다. WSL을 미러링 모드로 바꾸면 `127.0.0.1:11434`를 쓴다. 접속이 안 되면 Windows 방화벽에서 11434 사설망 인바운드를 확인한다. `dev.mjs`는 `ip route`로 게이트웨이를 찾고, 실패하면 `127.0.0.1`을 시도한다.
- 포트: web 5173 · gateway 8787 · forecast 8010 · records 8030 · Ollama 11434.
- `.env`: `DATA_GO_KR_KEY` `KMA_KEY` `OLLAMA_HOST` `OLLAMA_MODEL_FAST` `OLLAMA_MODEL_WRITE` `CROWDCAST_TODAY`(데모 기준일 고정) `DEMO_MODE`.

## 9. 코드 규칙 (요약 — 정본은 `AGENTS.md` §5)
- 파일 맨 위에 **파일 역할 한 줄 주석**, 코드 **한 문단(함수·클래스·의미 있는 블록)마다 바로 위에 한 줄 한국어 주석**.
- **기능별로 파일을 나눈다**: 한 파일 = 한 책임. 라우트·도구·의도·섹션·지표는 각각 파일 하나. 300줄을 넘으면 나눈다.
- 계층을 섞지 않는다: 라우트(입출력) → 서비스(로직) → 저장소/클라이언트(외부).
