## 3. Python 백엔드 고도화
| 영역 | v3 | v4 | 우선 | 이유 |

| 구간 보정 | 직접 구현한 CQR | **MAPIE**(conformal) | P0 | 검증된 구현, 코드가 줄어든다 |
| 근거 그래프 | 없음 | **rdflib + pySHACL + pyoxigraph** 별도 서비스 | P0 | 온톨로지·SHACL·SPARQL 표준 도구, 서버 설치 없이 파일 저장 |
| 두 번째 모델 | 없음 | **PyMC 계층 베이지안**(유형·시도 부분 풀링) | P1 | 소표본에 강하고 확률이 자연스럽다. 백테스트로 LightGBM과 비교하고 "두 모델이 합의한 구간"을 근거로 쓴다 |

## 4. 예보팀 런타임 (gateway, 상세는 `10`)
- **폴더**: `src/team/lead/`(분류·플레이북·게이트·발행), `src/team/analysis/` `verification/` `report/`(팀원 하나 = 파일 하나), `src/team/runtime/`(실행기·예산·트레이스·SSE).
- **공통 인터페이스**: `id` · `team` · `usesLlm` · `budgetMs` · `run(ctx) → { facts, evidence, claims, status }`. 실행기가 병렬·순서·시간 예산을 관리하고, 매 단계 `agent_status`를 SSE로 보낸다.
- **블랙보드**: 팀원은 결과를 서로 직접 주고받지 않고 **세션 근거 그래프**(knowledge)에 쓴다. 게이트는 그래프 구조에 대한 SHACL 검증 + 숫자·판정 문구의 코드 대조다(`09` §0).
- **발행**: 문장은 `draft → candidate → published`로 바뀌고, **발행된 뒤에만** SSE로 화면에 나간다. 숫자 카드(예측 서비스의 결정적 결과)는 게이트 A를 통과하면 먼저 보낸다(`10` §3).
- **LLM**: `src/llm/ollama-client.ts` 한 곳. 스키마 강제(`format`)·타임아웃·가짜 LLM 모드(`LLM_MODE=fake`).

### 4-4. B·C 에이전트
- **B 분석 자동화**(forecast): 1주차 `crowdcast pipeline run`(fetch → labels → features → train → backtest → batch → publish, 단계마다 Pandera·게이트), 2주차 Dagster 자산으로 이전. 마지막에 `pipeline/summary.py`가 Ollama로 실행 요약(숫자 자리표시자). publish 때 모델 버전·학습 범위를 기준 그래프에 올린다.

## 7. 해·날씨
- **해**: 웹에서 `suncalc`로 계산(사용자 위치 또는 선택한 행사장, 선택한 시각). 키가 필요 없다.
- **날씨**: forecast `GET /v1/weather?lat&lng&at` → `{ sky, pty, temp, pop, source, fetched_at }`.
  - 지금 = 기상청 초단기실황(`getUltraSrtNcst`), ~D+3 = 단기예보(`getVilageFcst`), ~D+10 = 중기예보(`getMidLandFcst`·`getMidTa`), 그 이후 = "정보 없음".

## 9. 계약 관리
- 정본: `packages/contracts/schemas/*.schema.json`(JSON Schema 2020-12). 도메인 객체: `event`, `event-draft`, `forecast`, `judgment`, `factor`, `evidence`, `claim`, `agent-status`, `gate-report`, `similar-event`, `region-baseline`, `weather`, `festival-summary`, `plan`, `plan-section`, `ledger-entry`, `insight`, `backtest-summary`, `sse-event`.
- JSON-LD 컨텍스트: `packages/contracts/jsonld/context.jsonld` — `evidence`·`claim`의 JSON 필드를 온톨로지 IRI로 잇는다.
- 코드 생성: TS 타입(`json-schema-to-typescript`) + Ajv(`ajv/dist/2020`), pydantic v2(`datamodel-code-generator --output-model-type pydantic_v2.BaseModel`), PHP는 opis/json-schema. 도구 버전·옵션 고정, 생성물 커밋, 재생성 후 diff 없음.
- 공통 규칙: 객체마다 `additionalProperties: false`, 날짜 ISO 8601(KST), 값 없음은 `type: [..., "null"]`, 금액·인원은 정수.
- 먼저 검증(T-001): 대표 계약 `forecast` 하나를 TS·Python·PHP에서 로드해 같은 정상·오류 픽스처를 똑같이 판정하는지 확인한 뒤 확장.

## 11. 로컬 실행
### 11-1. 한 번만 (`npm run setup`)
1. Node 22(설치됨), uv(설치됨) → `uv python install 3.12`
2. PHP 8.5 + Composer: `sudo apt install php-cli php-sqlite3 php-xml php-mbstring php-zip php-gd composer`(사람). 완료: `php -v` 8.5.x, `php -m`에 pdo_sqlite·xml·mbstring·zip·gd, `composer -V`
3. `npm install` · `uv sync` · `composer install`
4. `node scripts/fetch-assets.mjs`: 시군구 경계(라이선스 확인), Protomaps 한국 영역 PMTiles(전국 배경 maxzoom 13 + **시범 행사장 3곳 줌 15 추출**, 빌드 날짜 고정) + glyph·sprite(2D용), Pretendard → `data/external/` → `apps/web/public/`에 링크. Vite 정적 제공의 **HTTP Range 동작을 T-000에서 확인**(안 되면 gateway 정적 라우트)
5. Ollama 모델 확인·받기(`POST $OLLAMA_HOST/api/pull`)

### 11-2. 매번 (`npm run dev`)
- `scripts/dev.mjs`: `OLLAMA_HOST` 결정 → 앱 서비스 5개(web·gateway·forecast·knowledge·records) 기동 → **앱 서비스 health만** 최대 60초 대기 → 주소 출력. Ollama 상태는 따로 표시만 한다(꺼져 있으면 템플릿 모드).
- **WSL → Windows Ollama**(9/24 확인): Windows Ollama가 `OLLAMA_HOST=0.0.0.0:11434`로 바인딩(사용자 환경변수), WSL NAT 모드라 WSL 기본 게이트웨이 IP(`172.20.32.1`, 재부팅하면 바뀔 수 있음)로 접속. 미러링 모드면 `127.0.0.1`. 안 되면 Windows 방화벽 11434 사설망 인바운드 확인. `dev.mjs`는 `ip route`로 게이트웨이를 찾고 실패하면 `127.0.0.1`.
- 포트: web 5173 · gateway 8787 · forecast 8010 · knowledge 8020 · records 8030 · Ollama 11434.
- `.env`: `DATA_GO_KR_KEY` `OLLAMA_HOST` `OLLAMA_MODEL_FAST` `OLLAMA_MODEL_WRITE` `CROWDCAST_TODAY`(데모 기준일) `DEMO_MODE` `LLM_MODE`.
