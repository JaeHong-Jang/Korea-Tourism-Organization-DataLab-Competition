## 3. 피처와 공개 시점
- 행사: 유형, 기간(일), 주말·공휴일 포함 일수, 시간대, 무료 여부, 주최 유형, 회차(신규/반복), 예산(log, 결측 허용), 불·폭죽·산·수면 여부
- 이력: 전회차 실측(골드), 전회차 지자체 발표치, 전회차 대비 기간 변화
- 개최지: 시군구 평시 일방문자·외지인 비중, 주말 배수, 인구, 관광지 개최 여부
- 관심도: TMAP 검색 D-14 이전 4주 추세(확보 시)
- 달력: 월, 연휴 길이
- **누수 금지**: 개최 이후 데이터, 당해 지자체 발표치, 당일 날씨(날씨는 D-7 재예보에서만)
- **공개 시점 규칙**: **외부 정보에서 온** 피처 값마다 관측일과 별도로 `available_at` = 관측일 + 반영 지연을 기록하고, `available_at ≤ as_of`(= 개최일 − 14)만 쓴다(행사 속성은 요청 입력 — 아래 "두 정의"). **9/25 실측(벌크 수집)**: data.go.kr 15101972는 9/25 현재 **8/25까지만** 준다(8/26~9/20은 0행) → 관측 지연 약 31일. 따라서 이 API의 반영 지연은 **35일**(관측 31일 + 여유 4일)로 둔다(이전 가정 4일은 데이터랩 웹 기준 추정이었고 API에는 맞지 않는다). TMAP 약 6일·신한카드 약 11일은 확인 전 가정. `features/availability.py`가 검사하고 위반하면 파이프라인이 멈춘다.
- **행사 속성과 백테스트의 두 정의(9/25 T-203·계획 리뷰로 정함)**: 실시간 예보에서 행사 속성(유형·일정·기간·예산·주최·요금·위험 요소)은 주최 담당자가 **요청할 때 주는 입력**이다(외부 정보만 D-14 규칙). 백테스트는 이 사용 방식과 같게 두 가지를 **나눠 보고**한다.
  - **기본 = 조건부 백테스트**: "행사 속성이 주어졌을 때"의 예보 성능. 행사 속성은 문체부 계획 문서 값을 입력으로 쓰고, **외부 정보(방문자·전회차 실측·검색 등)만** `available_at ≤ as_of`. 서식4·S6에 이 정의 문장을 그대로 적는다(당시 공개 여부를 입증하지 않은 행사 속성을 쓴다는 한계 포함).
  - **참고 = 파일명 날짜 기준 민감도**(엄격한 D-14 입증이 아님): 계획 문서 파일명에 날짜가 있는 해(2018-06-05 · 2019-02-27 · 2025-03-21)에서 `as_of ≥ 그 날짜`인 행만 행사 속성을 쓰고 나머지는 결측으로 둔 성적을 별도 표로. 파일명 날짜가 실제 공개일·그날 문서 버전임은 **입증되지 않았다**고 표에 적는다. 날짜를 모르는 해(2017·2021·2022·2023·2026)와 사후 작성 가능성이 있는 해(2020 "현황" 10-16 · 2024 "홈페이지 게시" 09-30)는 이 표에서 행사 속성을 결측으로 둔다(가정 날짜로 채우지 않는다). **행사 속성까지 D-14 공개가 입증된 백테스트는 공식 공개 기록이 없어 지금은 만들 수 없다** — 서식4에 한계로 적는다.
  - 발표 방문객·실제 개최 여부 같은 사후 값은 어느 쪽에서도 피처로 쓰지 않는다. TourAPI로 채운 일정은 `date_available_at`.
- **달력**: 법정 공휴일·대체공휴일(규칙으로 미리 정해짐)은 쓰고, **임시공휴일**은 지정 시각을 복원할 수 없어 백테스트 피처에서 뺀다.
- 과거 발행본을 복원할 수 없는 피처(집중률 API의 "향후 30일")는 백테스트에 넣지 않고 실시간 예보에만 쓴다.
- 결측 대체·보정비율·유사 행사 검색도 각 학습 구간의 자료만으로 계산한다.

## 4. 순간 최대 환산 (가정)
```
순간 최대 = 일평균 방문객 × 피크일 계수 × 동시체류율
피크일 계수 = 가장 붐비는 날 ÷ 일평균   (가정 ①)
동시체류율 = min(1, 평균 체류시간 ÷ 운영시간 × 피크계수)   (가정 ②)
```
- **피크일 계수(가정 ①)**: 1일 행사 1.0, 2~3일 1.3, 4일 이상 1.5, 주말이 끼면 +0.1, 범위 ±0.2. 실버 자료(시군구 일별 순증의 날짜별 분포)로 P1에 다시 추정한다.
- 동시체류율은 가장 붐비는 날의 운영시간으로 계산한다.

| 유형 | 기준 id | 운영(h) | 체류(h) | 피크계수 | 동시체류율 | 범위(체류 ±20%) |
|---|---|---|---|---|---|---|
| 불꽃·드론쇼 | `as-concurrency-fireworks` | 3 | 2.5 | 1.2 | 1.00 | 0.80~1.00 |
| 공연·음악(야간) | `as-concurrency-performance` | 4 | 3 | 1.2 | 0.90 | 0.72~1.00 |

| 먹거리·장터 | `as-concurrency-food` | 10 | 2 | 1.8 | 0.36 | 0.29~0.43 |

## 5. 모델
- **처리 도구**: 변환은 Polars, 집계·조인은 DuckDB(Parquet 위 SQL, spatial 확장으로 좌표 → 시군구), 표 검증은 Pandera 스키마(열 타입·범위·결측·고유성). 게이트(§8)는 Pandera 검사 결과를 그대로 쓴다.
- **기본**: LightGBM 분위수 회귀(α = 0.1/0.5/0.9), 대상 log1p(일평균 방문객), 얕은 트리(num_leaves ≤ 15, min_data_in_leaf ≥ 10).
  - **단조 제약 금지**: LightGBM 4.6은 quantile 목적함수에 `monotone_constraints`를 주면 치명적 오류로 중단한다(`gbdt.cpp` 확인). 버전을 고정하고, 합성 데이터 호환성 테스트를 모델 task 착수 조건으로 둔다.
- **구간 보정**: CQR(MAPIE 구현 사용). 평가 연도 Y마다 **학습 ≤ Y−2, 보정 Y−1, 평가 Y**. "80% 보장"이라고 말하지 않고 **목표 포함률 80%**와 실제 포함률(표본 수·구간 폭)을 보고한다.
- **최종 분포 하나에서 모든 숫자 계산**(`models/distribution.py`):
  1. 보정된 p10·p50·p90을 정렬해 교차를 없앤다.
  2. log 공간에서 세 점을 단조 보간하고, 꼬리는 로그정규로 이어 CDF를 만든다.
  3. CDF에서 일 방문객을 샘플링하고, 샘플마다 동시체류율(체류시간 범위)을 곱해 순간 최대 샘플을 만든다.
  4. 중앙값·80% 구간·P(≥1,000)·P(≥5,000)을 **같은 샘플에서** 계산한다.
  5. 순서(p10 ≤ p50 ≤ p90)와 확률 일관성(p50 > 1,000이면 P ≥ 50%)을 단위테스트로 검사한다.
- **기준선**: B0 유형 중앙값, B1 전회차 실측 그대로, B2 주최측 **사전 예상치**(개최 전 발표, 단위가 일평균 방문객과 같은 경우만. 지자체의 사후 발표 방문객은 B2가 아니다).
- **설명**: SHAP 상위 5개 → 요인 JSON(`factor` 스키마) → gateway가 문장으로 만든다.
- **OOD**: 유형×규모 조합의 학습 표본 < 5 또는 피처가 학습 범위 밖 → `ood: true`.
- **두 번째 모델(P1)**: PyMC 계층 베이지안(유형·시도 부분 풀링, log 규모). 같은 롤링 백테스트로 비교하고, 두 모델 구간이 겹치는 정도를 `ModelEvidence`("두 모델 합의")로 쓴다. 성적이 나쁘면 근거로만 쓰고 기본 모델은 바꾸지 않는다.
- **D-7 재예보(P1)**: 기상청 예보(강수확률·기온)로 유형별 보정계수를 곱한다. 계수는 과거 강수일의 실버 순증 비교로 추정한다(표본이 부족하면 "보정 없음 + 날씨 주의 문구").

> **9/25 T-103 실측과 게이트 정리**: 실버 후보 1,486건 중 음수 25.7%(기존 게이트 < 5% 미충족), SNR 중앙값 0.78. 유의 신호(|SNR| > 3)만 보면 양수 250 · 음수 9(3.5%). 해석은 **가설**이다 — 작은 행사는 시군구 합계를 거의 움직이지 않아 잡음이 지배하고, 유의 음수는 추석·벚꽃 주말처럼 연휴·계절 효과가 섞인 경우로 보인다(사례별 기준선·σ·일정은 QC 표로 확인).
> - **실버 부호 검사**(학습·명절 제외 **전** 후보, 부호 있는 원래 순증으로): ① **중단** — 유의 신호(|SNR| > 3) 중 음수 비율 ≥ 5% ② **경고(임시 운영 기준 — 검증 전)** — 전체 후보 음수 비율 > 50%(저신호가 많으면 정상이어도 40%대가 나오므로 중단 기준으로 쓰지 않는다) ③ **중단** — 유의 신호 **비율**(유의 수 ÷ 후보 수)이 직전 실행의 **같은 연도 모집단**에서 80% 미만으로 떨어짐, 첫 실행은 유의 신호 ≥ 30건이 최소 조건 ④ SNR 결측은 σ = 0일 때만 생긴다(기준선 표본 < 3은 후보가 되기 전 구조적 제외) — σ = 0이면 SNR = null, 후보 분모에는 넣고 유의 판정·학습에서는 빼며 `zero_sigma` 건수로 보고. σ가 있는데 SNR이 결측이면 계산 오류로 보고 **중단**. 유의 신호 0건이면 중단 ⑤ 연도·시도별 순증 분포 표. **오류 주입 테스트**로 ①·③이 실제로 잡는지 보인다(순증 부호 뒤집기 → ①, 기준선 날짜 1주 밀기·지역 코드 섞기 → ③). QC에 각 검사의 분자·분모와 유의 음수 사례별 기준선·σ·일정을 남긴다.
> - **명절 겹침(`holiday_overlap`)**: 행사일이 설·추석 연휴(공휴일 표의 설날·추석과 그 대체공휴일 — 날짜 범위 고정)와 하루라도 겹치는 실버는 부호와 관계없이 학습·실버 백테스트 채점에서 빼고, 연도·유형별 제외 수와 남은 표본을 보고한다. 명절 행사는 골드가 있으면 골드로만 평가하고, 없으면 "채점 불가" 건수로 공개한다. 사전 등록(T-207) 선정 규칙도 등록 전에 같은 제외를 고정한다. 비명절 성적을 명절 행사로 일반화하지 않는다. 벚꽃 같은 계절 교란은 이 규칙으로 해결되지 않으며, 한계로 적는다.
> - **G0(같은 날)**: 정의 일치 골드 5건(< 30) — H2(축제 CSV 64개) 전. T-203 v1은 단순 모델(유형×규모 계층 중앙값 + 전회차)과 LightGBM(실버 + 골드)을 **둘 다** 같은 백테스트로 보고하고, 주 모델은 §11 규칙(아래 세 갈래)으로 **평가 전에** 정해 라벨 스냅샷 해시와 함께 고정한다. H2가 들어오면 T-203b가 새 버전으로 다시 판정하고, 이미 등록한 사전 등록 예보는 그대로 둔다.

## 12. 근거 조각 발행 (예측 서비스 → 근거 그래프, `09`)
예측 서비스의 모든 응답은 결과와 함께 `evidence[]`를 준다. id는 같은 입력이면 같은 값이 나오게 만든다(해시 기반).
| 결과 | 근거 종류 | 반드시 담을 것 |
|---|---|---|
| 개최지 평시 방문 | `DataEvidence` | 데이터셋(15101972 또는 데이터랩 원자료 메뉴), 기간, 값·단위, `available_at` |
| 방문객 구성·유입 권역 | `DataEvidence` | 데이터랩 지역별 관광현황 메뉴, 기간, 비율 |
| 유사 행사·전회차·골든 | `CaseEvidence` | 행사 id·연도, 실측·발표 값과 **단위 메타데이터**(§2), 출처 |
| 예측 분포·요인 | `ModelEvidence` | 모델 버전·학습 범위, p10·p50·p90, 요인 이름·기여도 |
| 예측에 쓴 피처 | `Observation`(피처마다 1개) + `PredictionRun` | 피처 이름·값·데이터셋·관측일·**공개일(available_at) 정확히 1개**·지역, 예보 기준 시점(as_of). 누수 검사(S09)의 입력 |
| 순간 최대 환산 | `AssumptionEvidence` | 유형별 동시체류율 값·범위·출처(가정/매뉴얼) |
| 판정 | `RuleEvidence` | 규칙 id, 법정/자체, 조항(법정일 때), 입력값 |
| 체크리스트 항목 | `RuleEvidence` | 규모 외 위험 규칙 id, 켜진 이유(행사 정보 필드) |
- 근거가 없는 결과는 응답하지 않는다(계약 테스트로 확인). 근거 조각은 게이트웨이가 세션 그래프에 적재한다.
- 학습(T-203)은 버전별 `models/<modelVersion>/model_card.json`(모델 버전·학습 데이터 범위·피처 목록·백테스트 요약)을 내고, 근거 그래프 서비스가 **사용 모델 포인터** `reports/backtest/promoted.json`이 가리키는 카드를 기준 그래프의 `ModelRun`으로 등록한다(P0 — 공유 `models/model_card.json`은 없다, §8).
