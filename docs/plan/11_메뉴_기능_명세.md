# 11. 메뉴 · 기능 · 세부 기능 명세

> v1 (2026-09-24). 화면(`03` §5)을 **메뉴 → 기능 → 세부 기능** 3단계로 쪼갠 구현·검토 기준이다.
> - 세부 기능 ID(예: `M2-F1-b`)는 task 파일과 UX 검토(`12`의 R-노드)에서 그대로 쓴다.
> - "수용"은 세부 기능이 끝났다고 말할 수 있는 최소 조건, "담당"은 구현 task다.
> - UX 검토는 이 표를 체크리스트로 쓴다: **메뉴마다 기능이 눈으로 구분되는가, 세부 기능이 한 번에 찾아지는가, 처음 쓰는 사람이 설명 없이 끝까지 가는가.**

## 화면 구분 원칙 (UX 검토 기준)
1. 한 화면의 기능 블록은 **제목 + 한 줄 설명**을 가진 카드·패널로 나뉘고, 블록 사이 여백이 블록 안 여백보다 크다.
2. 한 화면에서 주요 행동 버튼은 하나(예: S2는 "보내기", S3은 "계획 초안 받기")만 채운 버튼이고, 나머지는 보조 버튼이다.
3. 메뉴 이름과 화면 제목이 같다. 메뉴를 옮겨도 헤더·필터·목록 위치가 흔들리지 않는다.
4. 처음 쓰는 사람이 설명 없이 **예시 칩 → 예보서 → 초안 받기**까지 3번 클릭 안에 간다.
5. 모든 숫자에 단위와 출처(근거 칩·ⓘ)가 붙는다.
