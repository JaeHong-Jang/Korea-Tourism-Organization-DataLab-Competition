# 03. 제품 기획서 — 인파예보(CrowdCast) 완성품 정의

> v3 (2026-09-24). 이 문서는 **무엇을, 누구를 위해, 왜** 만드는지와 **화면·기능의 완성 기준**을 정한다.
> 디자인은 `04`, 기술은 `05`, 데이터·모델은 `06`, 일정·작업은 `07`, 평가 기준 대응은 `08`에 있다.

---

## 0. 한 줄 정의
**"행사 열기 전에, 인파를 예보합니다."**
행사 정보를 한 줄로 말하면 AI가 데이터랩 데이터로 **순간 최대 인파를 예보하고, 안전관리계획 수립 대상인지 판정하고, 계획 초안까지 만들어 주는** 웹 서비스다. 전국에서 다가오는 행사의 인파 예보는 **지도 대시보드**로 한눈에 보여 준다.

| 누구에게 | 무엇을 바꾸나 |
|---|---|
| 지자체 축제·행사 담당 주무관 | 계획 수립 여부, 안전요원·통제·교통 규모를 "감"이 아니라 데이터로 정한다 |
| 대학·상인회·민간 주최자 | 1,000명 기준을 몰라서 계획 없이 여는 일을 막는다 |
| 시·도 안전 담당 | 관내 행사를 위험 순으로 보고 점검 우선순위를 정한다 |

## 1. 왜 필요한가

### 1-1. 법은 "예상"을 요구하는데 계산할 방법이 없다
- 「재난 및 안전관리 기본법 시행령」 제73조의9: 축제 기간 중 **순간 최대 관람객 1,000명 이상 예상** 지역축제는 안전관리계획 수립 대상이다. 1,000명 미만이어도 **산·수면** 개최, **불·폭죽·석유류·가연성 가스** 사용 행사는 대상이다.
- 예상 인원은 주최자가 스스로 정한다. 산정 표준도 도구도 없다.

### 1-2. 틀리면 생기는 일
| 사례 | 주최측 예상 | 실제 | 결과 | 실패 유형 → 서비스의 답 |
|---|---|---|---|---|
| 2025.10.18 인천 중구 영종 불꽃축제 | 2,000 | 30,000+ | 극심한 교통 혼잡 | 규모 산정 15배 오차 → **규모 구간 + 인력·교통 산정** |
| 2025.11.2 인천 남동구 약사사 산사음악회 | 500 | 1,000+ (누적 1,500) | 112 신고, 50여 명 투입, 공연 15분 중단 | 기준 미만 오판 → **확률 판정 + "경계선: 수립 권고"** |
| 2026.9 안성 공도읍 '나눔의 녹색장터' | 1,000 미만 | — | 트럭 돌진, 사상자 7명. 계획 대상이 아니어서 차량·보행 동선 분리 없음 | 규모 외 위험 → **1,000명 미만에도 위험요소 체크리스트** |

### 1-3. 기존 도구가 비워 둔 시점
```
D-60 기획 ── D-30~D-14 계획 수립·심의 ── D-7 준비 ── D-0 당일 ── D+7 사후
          ▲ 인파예보: 예보·판정·초안 (D-7 재예보)     ▲ 행안부 현장인파관리      ▲ 인파예보: 채점
                                                     (기지국 실시간 밀집도)    (데이터랩 실측)
```
- 행안부 현장인파관리시스템은 **당일 실시간** 감시다. KTO 관광지 집중률 예측은 **기존 관광지의 상대치**(최성수기=100)다. 데이터랩 지역 방문 예측은 시군구 총량이다.
- → **개최 전 계획 단계에 행사 단위 절대 인원**을 주는 도구가 없다.

### 1-4. 왜 AI 에이전트인가
- 주최자는 행사 유형 분류, 행정코드, 필요한 변수를 모른다 → AI가 자연어를 구조화하고 **빠진 것만 되묻는다**.
- 행사마다 조회할 데이터가 다르다(반복 행사는 전회차 실측, 신규는 유사 행사와 개최지 평시 방문).
- 결과를 설명과 문서로 바꾸는 일은 LLM이 잘한다.
- **숫자는 LLM이 만들지 않는다.** 예측·판정은 코드가 하고 LLM은 추출·의도 파악·설명·문서만 맡는다. 로컬 LLM 스모크 테스트(9/24)에서 자유 도구 호출은 연도·시군구를 틀렸고, 스키마 강제 추출은 정확했다. 이 설계가 그 결과에 맞춘 것이다(`05` §3).

## 3. 제품 원칙
1. **한 줄로 시작하고 카드로 확인한다.** 채팅만 있으면 불투명하고, 폼만 있으면 번거롭다. AI가 채운 필드는 칩으로 보이고 클릭해 고친다.
2. **예보처럼 읽힌다.** 큰 숫자 하나, 범위, 확률, 등급으로 3초 안에 읽힌다.
3. **숫자마다 출처가 있다.** 모든 수치에 ⓘ를 달아 데이터랩 메뉴·API명, 유사 행사, 가정값을 보여 준다.
4. **결정으로 끝낸다.** 모든 결과 화면 하단에 "다음 할 일"을 둔다.
5. **공무원 업무 환경을 우선한다.** 로그인 없이, 1366px 기준, A4 인쇄, docx(한글에서 열림), 표 복사.
6. **모르면 모른다고 한다.** 유사 사례가 부족하거나 학습 범위 밖이면 "참고용" 배지, 넓은 구간, 초안 비활성.
7. **AI가 멈춰도 서비스는 돈다.** 로컬 LLM이 느리거나 꺼져도 예측·판정·예보서는 템플릿 문장으로 나온다.

### F1. 전국 인파 예보 지도
- **목적**: 시·도 담당과 심사위원이 "전국에서 어떤 행사가 위험한지"를 한눈에 본다.
- **구성**: KPI 띠(예보 행사 수·수립 대상·권고·대규모) / 주간 타임라인(등급별 누적 막대 + 기간 선택) / 필터(기간·시도·유형·등급) / 지도(시군구 코로플레스 + 행사 마커) / 카드 목록(위험 순).
- **지도 상호작용**: 마커 크기 = 예상 순간 최대(p50), 색 = 등급. 호버하면 툴팁, 클릭하면 카드 목록에서 강조하고 요약 패널을 연다. 줌이 낮으면 클러스터로 묶는다. 코로플레스는 "평시 외지인 방문"과 "기간 내 예보 인파 합계" 중에서 전환한다.
- **데이터**: TourAPI `searchFestival2`로 받은 10~12월 행사 + 문체부 지역축제 정보 → 매일 밤 일괄 예보(B 에이전트).
- **수용 기준**: 300개 행사 마커와 시군구 250개 폴리곤이 60fps에 가깝게 움직인다. 필터·지도·목록이 서로 동기화된다. 오프라인에서도 지도가 뜬다(로컬 타일).

### F2. AI 예보 상담
- **흐름**: ① 한 줄 입력 → ② AI가 행사 카드 작성(유형·일시·장소·요금·홍보) → ③ 필수값이 없거나 모호하면 되묻기 버튼(예: "중구 → 서울 중구 / 인천 중구 / 부산 중구…") → ④ 예측·판정 → ⑤ 설명 → ⑥ 다음 할 일.
- **후속 질문(what-if)**: "비 오면?", "일요일로 바꾸면?", "유료로 하면?", "왜 이렇게 많아?", "비슷한 행사 보여 줘", "계획 초안 만들어 줘". 의도를 분류한 뒤 코드가 해당 도구를 다시 실행한다.
- **작업 로그**: "✓ 장소 → 인천 중구", "✓ 평시 방문(데이터랩 API)", "✓ 유사 행사 5건", "✓ 예측 모델 v1.2". 심사용 "데모 로그" 토글을 켜면 호출 요약·지연·데이터 출처까지 보인다.
- **수용 기준**: 로컬 LLM에서 첫 예보서까지 15초 이내(스모크 테스트 기준 추출 1.5초). LLM을 끄면 템플릿 문장으로 같은 결과가 나온다.

### F3. 예보서
- **구성(위→아래)**: 행사 카드 → **판정 배너**(등급·사유·법정/자체 기준 구분) → **핵심 수치**(예상 순간 최대·80% 구간·피크 시간·최대 일 방문객) → **구간 막대**(1,000명 기준선·주최측 예상 표시) → **근거**(상향/하향 요인) → **유사 행사 카드 3~5** → **개최지 평시**(요일 패턴 스파크라인) → **방문객 구성**(현지인/외지인/외국인, 유입 권역) → **시간대 곡선(가정)** → **준비 체크리스트**(규모 외 위험 포함) → **다음 할 일**.
- **공유·인쇄**: `/f/{id}` 링크, A4 한 장 인쇄(면책 문구 포함).
- **수용 기준**: 모든 숫자에 출처 ⓘ가 있다. 화면 숫자와 도구 결과 JSON이 일치한다(자동 테스트).

### F4. 안전관리계획 초안
- **목차**: 개요 / 조직·임무 / 예상 인원·시간대 / 동선·대피로 / 안전 인력 배치 / 교통·주차 / 의료·화장실 / 기상·비상 대응 / 규모 외 위험.
- **숫자 필드**(예상 인원, 시간대, 인력 산정)는 예보서에서 자동으로 들어간다(잠금 표시). 서술은 AI 초안으로 쓰고 "검토 필요" 하이라이트를 단다.
- **내보내기**: docx(한글에서 열림, 함초롬바탕·맑은 고딕, 표 서식 유지), 워터마크 "참고용 초안 — 담당자 검토 필수".
- **수용 기준**: 한글 2024에서 docx를 열었을 때 표·글꼴이 깨지지 않는다(사람 확인 1회).

### F5. 내 행사 (P1)
- 저장한 행사 목록, 상태(예보됨 / 재예보 필요 / 종료·실측 대기 / 채점 완료).
- **D-7 재예보**: 기상청 중기예보를 반영해 다시 예보하고 변화량을 보여 준다("강수 60% → 예상 −18%").
- **행사 후**: 실측 인원을 입력하거나 데이터랩 반영 후 자동 채점 → 다음 해 예보 개선 데이터로 쓴다.

### F6. 검증 센터
- **예측 vs 실측 산점도**(최대 일 방문객, log-log) + **환산 판정 사분면**(동시체류율 가정 포함 라벨).
- 지표 카드: MdAPE, 80% 구간 포함률(목표 80%, 표본 수 병기), 환산 판정 재현율, 기준선 대비 개선.
- **골든 케이스**: 영종·약사사 등의 당시 주최측 예상 / 모델(D-14 정보) / 실제 — 각 인원의 **단위**(순간/일/누적)를 함께 표시하고 같은 단위끼리만 포함 여부를 판정한다.
- **사전 등록 예보 채점판**: 등록 시각·해시·예보·실측·포함 여부, 채점 불가 건수 공개, 해시 체인 검증 버튼.
- **모델 카드**: 학습 데이터 범위, 피처, 한계, 버전.

### F7. 데이터 인사이트
- 문제 진단 지표 5~6개(`06` §7): 지자체 발표 vs 데이터랩 실측 괴리, 1,000명 경계선 행사 비중, 유형별 순간 밀집도, 평시 대비 순증 배수, 외지인 비중·유입 권역, 월·지역별 행사 밀도 지도.
- **데이터랩 활용 명세표**: 메뉴명·지표·기간·단위·용도. 서식4 "활용 데이터"와 같은 내용을 제품 안에서 보여 준다.

### F8. 운영 (P1)
- B 에이전트 실행 기록(단계·게이트·소요 시간·산출물 해시·AI 요약), C 에이전트 평가 결과, 데이터 최신성(마지막 수집일), 모델 버전 이력.

## 6. 사용 시나리오

### 6-1. 주무관 A — "대상인지, 몇 명인지"
1. S2에서 "11/8 토요일 오후 2시부터 9시까지 ○○천 둔치 먹거리 축제, 무료, 푸드트럭 30대" 입력.
2. AI가 "천 둔치"를 수면 인접으로 표시하고, 장소 후보 2개를 되묻는다 → 선택.
3. 예보서: 🟡 권고(1,000명 초과 34%), 순간 최대 610~1,450명. 규모 외 위험 체크리스트에 "푸드트럭 차량 진입 동선 분리".
4. [계획 초안] → docx 내보내기 → 결재 첨부.

### 6-2. 총학 B — "우리 축제도 해당돼요?"
1. "10월 둘째 주 목·금 저녁 대학 축제, 연예인 공연 있음" → AI가 날짜 후보를 되묻는다(10/8~9).
2. 🟠 대상(초과 확률 88%) → 체크리스트와 "학교 안전 담당·지자체 협의 필요" 안내 → 링크 공유.

### 6-3. 시·도 안전 담당 C — "어디부터 점검하지?"
1. S1에서 시도=경기, 기간=11월, 등급=🔴🟠로 거른다 → 카드 12개.
2. 카드 → 예보서 → 인쇄해 점검 회의 자료로 쓴다.

### 6-4. 심사위원 라이브 데모 (90초)
| 초 | 화면 | 말 |
|---|---|---|
| 0~15 | S1 지도 | "10월 전국 214개 행사, 이 중 61곳이 수립 대상입니다" |
| 15~50 | S2 | 심사위원이 말한 행사 입력 → 작업 로그에 데이터랩 호출이 찍히고 예보서가 채워진다 |
| 50~70 | S3·S4 | 판정 근거 → 초안 docx |
| 70~90 | S6 | "9/29에 공개 등록한 예보 N건 중 M건이 구간 안에 들어왔습니다" (해시 체인 검증) |

- 네트워크·LLM 장애에 대비해 저장된 트레이스를 같은 화면으로 재생하는 **데모 재생 모드**를 둔다.

## 7. 서비스 형태와 운영
- **로컬 실행 웹앱**: 서버 배포 없이 노트북 한 대에서 `npm run dev` 한 번으로 웹·게이트웨이·예측·기록 서비스와 로컬 LLM(Ollama)을 모두 띄운다(`05` §7).
- **오프라인 동작**: 지도 타일, 경계, 모델, 예보 결과를 모두 로컬에 둔다. 인터넷이 없어도 데모가 된다(데이터 갱신만 인터넷 필요).
- **개인정보**: 로그인 없음. 행사 정보만 저장한다.
- **면책**: 모든 예보서·초안에 "참고용 — 담당자 검토 필수", 순간 최대에는 "추정 산식 기반"을 표시한다.
