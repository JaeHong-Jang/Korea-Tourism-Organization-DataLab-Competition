# 03. 제품 기획서 — 인파예보(CrowdCast) 완성품 정의

> v4 (2026-09-24). **무엇을, 누구를 위해, 왜** 만드는지와 **화면·기능의 완성 기준**.
> 디자인 `04` · 기술 `05` · 데이터·모델 `06` · 일정·작업 `07` · 서식4 `08` · 근거 그래프 `09` · 예보팀 `10`.

## 0. 한 줄 정의
**"행사 열기 전에, 인파를 예보합니다."**
행사를 한 줄로 말하면 **예보팀**(AI 에이전트 12명 + 팀장)이 데이터랩 데이터로 순간 최대 인파를 예보하고, 안전관리계획 수립 대상인지 판정하고, 계획 초안까지 만든다. **모든 설명 문장에는 근거가 붙는다.** 전국에서 다가오는 행사는 **3D 미니 대한민국** 위에서 본다 — 예보 인원이 많을수록 블록 인형이 모이고, 장면은 실제 시각·날씨에 따라 낮·밤·비로 바뀐다.

| 누구에게 | 무엇을 바꾸나 |
|---|---|
| 지자체 축제·행사 담당 주무관 | 계획 수립 여부, 안전요원·통제·교통 규모를 근거 있는 숫자로 정한다 |
| 대학·상인회·민간 주최자 | 1,000명 기준을 몰라서 계획 없이 여는 일을 막는다 |
| 시·도 안전 담당 | 관내 행사를 위험 순으로 보고 점검 우선순위를 정한다 |

## 1. 왜 필요한가

### 1-1. 법은 "예상"을 요구하는데 계산할 방법이 없다
- 「재난 및 안전관리 기본법 시행령」 제73조의9: 축제 기간 중 **순간 최대 관람객 1,000명 이상 예상** 지역축제는 안전관리계획 수립 대상. 1,000명 미만이어도 **산·수면** 개최, **불·폭죽·석유류·가연성 가스** 사용 행사는 대상.
- 예상 인원은 주최자가 스스로 정한다. 산정 표준도 도구도 없다.

### 1-2. 틀리면 생기는 일
| 사례 | 주최측 예상 | 실제 | 결과 | 실패 유형 → 서비스의 답 |
|---|---|---|---|---|
| 2025.10.18 인천 중구 영종 불꽃축제 | 2,000 | 30,000+ | 극심한 교통 혼잡 | 규모 산정 15배 오차 → **규모 구간 + 인력·교통 산정** |
| 2025.11.2 인천 남동구 약사사 산사음악회 | 500 | 1,000+ (누적 1,500) | 112 신고, 50여 명 투입, 공연 15분 중단 | 기준 미만 오판 → **확률 판정 + "경계선: 수립 권고"** |
| 2026.9 안성 공도읍 '나눔의 녹색장터' | 1,000 미만 | — | 트럭 돌진, 사상자 7명. 계획 대상이 아니어서 차량·보행 동선 분리 없음 | 규모 외 위험 → **1,000명 미만에도 위험요소 체크리스트** |

### 1-3. 기존 도구가 비워 둔 시점
```
D-60 기획 ── D-30~D-14 계획 수립·심의 ── D-7 준비 ── D-0 당일 ── D+7 사후
          ▲ 인파예보: 예보·판정·초안 (D-7 재예보)     ▲ 행안부 현장인파관리      ▲ 인파예보: 채점
                                                     (기지국 실시간 밀집도)    (데이터랩 실측)
```
- 행안부 현장인파관리시스템은 **당일 실시간**, KTO 관광지 집중률 예측은 **기존 관광지의 상대치**, 데이터랩 지역 방문 예측은 시군구 총량. → **개최 전 계획 단계의 행사 단위 절대 인원**을 주는 도구가 없다.

### 1-4. 왜 에이전트 "팀"이고, 왜 "근거 그래프"인가
- 주최자는 유형 분류·행정코드·필요한 변수를 모른다 → 받아쓰기가 구조화하고 빠진 것만 되묻는다.
- 행사마다 조회할 데이터가 다르다 → 팀장이 플레이북으로 필요한 팀원만 부른다.
- 안전 판단은 **근거를 댈 수 있어야** 쓸 수 있다 → 모든 문장을 근거 그래프에 연결하고, 검증팀이 근거 구조는 SHACL로·숫자와 판정 문구는 코드로 검사한 뒤 통과한 문장만 내보낸다(`09` §0).
- **숫자는 LLM이 만들지 않는다.** 예측·판정은 코드가, LLM은 추출·분류·설명·문서만. 13명 중 LLM을 쓸 수 있는 역할은 5개이고, 새 예보 한 번에는 LLM을 2회만 부른다(`10` §0). 로컬 LLM 스모크 테스트(9/24)에서 자유 도구 호출은 연도·시군구를 틀렸고 스키마 강제 추출은 정확했다.

심사위원(발표 10/23)은 네 번째 사용자다. 90초 안에 "문제 → 데이터랩 데이터 → 예보팀 → 근거 → 검증 숫자"가 보여야 한다(§6-4).

## 3. 제품 원칙
1. **한 줄로 시작하고 카드로 확인한다.** AI가 채운 필드는 칩으로 보이고 클릭해 고친다.
2. **한눈에 읽힌다.** 큰 숫자 하나, 범위, 확률, 등급.
3. **모든 문장에 근거가 있다.** 설명 문장 끝의 근거 칩을 누르면 데이터랩 메뉴·규정·가정까지 따라간다. 근거 없는 문장은 나가지 않는다.
4. **지금을 반영한다.** 실제 시각·날씨로 장면이 바뀌고, 미래 행사는 그날 그 시각의 해와 예보 날씨로 보여 준다.
5. **결정으로 끝낸다.** 결과 화면 하단에 "다음 할 일".
6. **공무원 업무 환경을 우선한다.** 로그인 없이, 1366px 기준, A4 인쇄, docx(한글에서 열림).
7. **모르면 모른다고 한다.** 표본 부족·학습 범위 밖이면 "참고용", 넓은 구간, 초안 비활성.
8. **AI가 멈춰도 서비스는 돈다.** 로컬 LLM이 꺼져도 숫자·판정·근거 카드는 나오고 문장은 템플릿으로 대체된다.

### F1. 3D 미니 대한민국
- **장면**: 나무판 위 시군구 타일, 바다, 유형별 축제 모형(불꽃 발사대·무대·천막·화단…), 등급 깃발, 모형 주변 블록 인형(예보 p50에 비례, "인형 1개 = N명"). 카메라 비스듬히 내려다보기 + 틸트시프트.
- **데이터 모드**: 타일 색·높이 = 기간 내 예보 인파 합(순차 파랑) / 끄면 따뜻한 땅색.
- **떠 있는 패널**: 필터(기간·시도·유형·등급), 행사 목록(위험 순), 하단 타임라인(등급별 누적, P1 브러시), 날씨·테마 칩.
- **상호작용**: 무대에 호버하면 이름표, 클릭하면 카메라가 날아가 목록 강조 + 요약 패널 → [예보서]. 목록 클릭도 같은 동작.
- **정직한 표시**: "인원 규모는 예보값 비례 · 움직임은 연출".
- **수용 기준**: P0 — 행사 300개·정적 인형 2,000개에서 1366×768·DPR 1 기준 프레임 시간과 메모리를 **Ollama 추론을 동시에 돌린 상태로** 측정해 기록하고, 3D를 쓸 수 없으면 SVG 전국 지도 + 목록으로 같은 일을 할 수 있다. P1 — 측정 결과를 보고 인형 수·걷기·후처리를 늘린다(목표 RTX 2080 60fps, 저사양 30fps). 오프라인 동작.

### F2. 예보 상담 + 예보팀 작업판
- 흐름: 입력 → 받아쓰기(행사 카드) → 되묻기(모호한 장소·빠진 날짜) → 분석팀(동네지기·기록관 병렬 → 예보관) → 게이트 A → 보고팀(해설가·카드장인·브리핑) → 게이트 B → 팀장 발행.
- **작업판**: 팀장 1 + 3팀 × 4명 펫. 일하는 펫은 움직이고 말풍선 메모를 띄운다. 게이트를 통과하면 팀장이 도장을 찍는다. 위반이 있으면 해당 검증팀원이 손을 들고 내용을 보여 준다. 펫을 누르면 그 팀원의 작업 기록.
- 후속 질문: "왜 이렇게 많아?"·"계획 초안 만들어 줘"·"저장해 줘"(P0), "비 오면?"·"일요일이면?"·"유료면?"(P1).
- **수용 기준**: 시간 목표는 숫자 카드 5초·발행 15초(측정 전 가설, `10` §3에서 p50·p95로 확정). 문장은 검증·발행 뒤에만 화면에 나온다. Ollama를 끄면 템플릿 문장으로 같은 흐름이 끝난다.

### F3. 예보서 + 근거 서랍
- **예보서 탭**: 행사 카드 → 판정 배너(등급·사유·법정/자체) → 핵심 수치(순간 최대·80% 구간·피크 시간·최대 일 방문객) → 구간 막대 → 설명(문장마다 근거 칩) → 유사 행사 → 개최지 평시 → 방문객 구성 → 시간대 곡선(가정) → 준비 체크리스트 → 다음 할 일.
- **근거 서랍**(오른쪽): 칩 번호 순서대로 근거 카드(데이터·모델·규정·사례·가정·검증).
- **근거 지도 탭(P1)**: 문장 → 근거 → 출처 → 데이터셋 그래프.
- **행사장 3D 탭(P1)**: F9.
- **수용 기준**: 발행 문장 100%가 근거 칩을 가진다. 화면 숫자 = 도구 JSON(자동 테스트). A4 인쇄.

### F4. 안전관리계획 초안
- 목차: 개요 / 조직·임무 / 예상 인원·시간대 / 동선·대피로 / 안전 인력 / 교통·주차 / 의료·화장실 / 기상·비상 / 규모 외 위험. 숫자 필드는 예보서에서 자동(잠금), 서술은 계획서 에이전트 초안(섹션마다 근거 각주).
- docx(한글에서 열림, 함초롬바탕·맑은 고딕, 표 유지, 근거 각주), 워터마크 "참고용 초안 — 담당자 검토 필수". 편집기는 P1.

### F5. 내 행사 (P1)
- 상태: 예보됨 / 재예보 필요 / 종료·실측 대기 / 채점 완료. D-7 재예보(중기예보 반영, 변화량). 행사 후 실측 입력 → 채점.

### F6. 검증 센터 + 근거 대시보드
- 예측 vs 실측 산점도(최대 일 방문객) + 환산 판정 사분면(가정 포함 라벨).
- 지표: MdAPE, 80% 구간 포함률(목표 80%, 표본 수), 환산 판정 재현율, 기준선 대비 개선(비교 가능 표본 수).
- 골든 케이스(인원 단위 표시, 같은 단위끼리 판정), 사전 등록 채점판(해시 체인 검증), 모델 카드.
- **근거 대시보드**: 근거 없는 발행 문장 수(0), SHACL 통과율, 데이터랩 메뉴별 근거 사용 횟수, 규칙별 판정 수.

### F7. 데이터 인사이트
- 문제 진단 지표(`06` §7), 데이터랩 활용 명세표(실제 사용 확인된 것만), 카드마다 [서식4용 문장 복사].

### F8. 운영 (P1)
- B 실행 기록(단계·게이트·소요·산출물 해시·요약), C 평가 결과, 데이터 최신성, 모델 버전, 근거 그래프 크기.

### F9. 행사장 디오라마 (P1)
- 행사장 반경 1.5km: 건물(높이), 도로, 철도·지하철역(로컬 지도 타일에서 추출).
- **시간대 슬라이더**: 시간대 곡선(가정)에 따라 인형이 모였다 흩어진다. 차량은 도로를 따라 행사장 쪽으로, 지하철은 역에 정차.
- 행사일 그 시각의 해 위치·예보 날씨로 장면을 만든다. 불꽃 행사면 밤에 불꽃놀이.
- 범례: "인형 1개 = N명", "차량·열차 움직임은 연출(외지인 비중·교통수단 가정 반영)".

## 6. 사용 시나리오

### 6-1. 주무관 A — "대상인지, 몇 명인지, 근거는"
1. S2: "11/8 토요일 오후 2시~9시 ○○천 둔치 먹거리 축제, 무료, 푸드트럭 30대".
2. 받아쓰기가 수면 인접을 표시, 동네지기가 장소 후보 2개를 되묻는다 → 선택.
3. 예보서: 🟡 권고(1,000명 초과 34%), 순간 최대 610~1,450명. 체크리스트에 "푸드트럭 차량 진입 동선 분리"(근거: 규모 외 위험 규칙 + 안성 사례).
4. 근거 칩 [2] → "지역별 방문자수(데이터랩 API) · 평시 토요일 외지인 …" 카드 확인 → [계획 초안 받기] → 결재 첨부.

### 6-2. 총학 B — "우리 축제도 해당돼요?"
1. "10월 둘째 주 목·금 저녁 대학 축제, 연예인 공연" → 날짜 후보 되묻기 → 🟠 대상(88%) → 체크리스트·링크 공유.

### 6-3. 시·도 안전 담당 C — "어디부터 점검하지?"
1. S1에서 경기·11월·🔴🟠 → 판 위 무대 12곳이 강조 → 목록 → 예보서 → 인쇄.

### 6-4. 심사위원 라이브 데모 (90초)
| 초 | 화면 | 말 |
|---|---|---|
| 0~15 | S1 밤 장면 | "지금 서울은 밤, 흐림입니다. 10월 전국 214개 행사, 이 중 61곳이 수립 대상이에요" (인형이 모인 무대들) |

## 7. 서비스 형태와 운영
- **로컬 실행 웹앱**: 노트북 한 대에서 `npm run dev` 한 번으로 웹·게이트웨이·예측·근거 그래프·기록 서비스와 로컬 LLM(Ollama)을 띄운다(`05` §7).
- **오프라인 동작**: 3D 판·경계·모델·예보·지도 타일을 로컬에 둔다. 날씨·데이터 갱신만 인터넷이 필요하다.
- **개인정보 없음**, 로그인 없음.
- **면책**: 예보서·초안에 "참고용 — 담당자 검토 필수", 순간 최대 "추정 산식 기반", 3D "움직임은 연출".
