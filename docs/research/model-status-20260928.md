# 연구 모델 현황 정리 (2026-09-28)

결론부터: **발행 예보에는 여전히 기존 모델을 쓴다.** 가장 성적이 좋은 연구 모델은 v2(월별 재학습 + 앞선 회차 입력)이며, 모델 검증 화면에는 v2의 성적만 싣는다. 운영에 올리지 않은 이유와 경과는 이 문서와 각 실험 문서에만 둔다.

## 1. 실험 세 가지

| 실험 | 내용 | 결과 | 문서 |
|---|---|---|---|
| v1 | 실버 1,804행 전체, 월별 재학습 | 2025·2026 MAE 12,486 / 10,765. 채택 조건 미충족 | [silver-expansion-20260928/results.md](silver-expansion-20260928/results.md) |
| v2 | v1 + 앞선 회차 순증 입력 (변형 3개 사전 등록) | 2025·2026 MAE **12,360 / 9,823**. 채택 조건 7개 중 C1·C3 미충족 | [silver-v2-20260928/results.md](silver-v2-20260928/results.md) |
| 고정 분할 | 2023~24 학습 · 2025.1~8 검증 · 2025.9~2026.8 테스트, 한 번 학습 | 검증 기준 통과, 테스트 MAE 11,371로 월별 재학습(v1 11,278 · v2 10,683)보다 나쁨 | [silver-holdout-20260928/results.md](silver-holdout-20260928/results.md) |

## 2. 운영에 올리지 않은 이유

1. **2024 개발 연도 기준(C1) 미충족.** v1·v2 모두 2024년 MAE가 유형별 중앙값(11,208.4)보다 컸다(v1 11,272.3, v2 11,319.1). 2024년은 학습 자료가 294~584행뿐이고, 앞선 회차가 있는 행사가 40%에 그친다. 고정 분할에서 2023~24를 학습에 쓰자 검증 기준을 넘었으므로, 설계보다 **자료 기간 부족**이 원인이다.
2. **큰 행사 과소예측(C3) 미해결.** 2025·2026 큰 양수 순증 124건(2023년 90% 분위수 25,692.5명/일 이상)에서 v2도 평균 약 3만 명/일을 적게 예측했고, 구간 포함률은 31.6%였다(v1 25.4%, 기준 50%). 앞선 회차가 없는 신규·단발 대형 행사의 규모를 알려 줄 사전 공개 신호가 없다.
3. **조건을 결과 뒤에 바꾸지 않았다.** 각 실험은 실행 전에 설계와 조건을 문서로 고정하고, 그 SHA-256을 실행 기록에 남겼다.

## 3. 알게 된 것

- 앞선 회차 순증은 지역 평시 규모 다음으로 중요한 입력이다(중앙값 모델 분할 이득 약 17%).
- 한 번 학습한 모델은 시간이 지나면 나빠진다. 운영하려면 월별 재학습이 맞다.
- 큰 행사는 분할을 바꿔도 풀리지 않았다. SNR>3만 학습한 모델이 큰 행사 포함률은 높지만(고정 분할 테스트 81.8%) 전체 MAE는 가장 나쁘다.

## 4. 운영에 올리려면

1. 2023년 이전 실버 라벨을 확보해 개발 연도의 학습 이력을 늘린다.
2. 공개 시점을 증명할 수 있는 행사 규모 자료(사전 공지 수용 인원 등)를 모은다.
3. 앞으로 열리는 행사의 사전 저장 예보를 채점해 전향 근거를 만든다. 2025·2026은 이미 여러 번 본 자료라 독립 시험이 아니다.

## 5. 웹 화면과의 관계

- `/validation` 상단 카드·"어떻게 나눴나"·"계산 기록"과 `/graph` 연구 근거 카드는 v2 성적만 보여 준다. 상태 표시는 "연구 모델 · 발행 예보 미적용"이다.
- 화면 수치는 `apps/web/src/features/validation/research-v2-data.ts`에 있고, 실행 산출물에서 생성한다. 손으로 고치지 않는다.

```bash
PYTHONPATH=services/forecast/src python -m crowdcast.research.silver_v2.web_export \
  --repo . --output apps/web/src/features/validation/research-v2-data.ts
```

- `reports/backtest/`는 `.gitignore` 대상이라 실행 산출물은 저장소에 없다. 재생성하려면 각 결과 문서의 재현 절차로 산출물을 먼저 만든다.

## 6. 실행 환경 메모

- Windows의 저장소 `.venv/Scripts/python.exe`가 Device Guard 정책에 막혀, 이번 실험은 WSL에서 별도 환경(`UV_PROJECT_ENVIRONMENT=$HOME/.venvs/crowdcast`, `uv sync --package crowdcast-forecast --frozen`)으로 실행했다.
- WSL에 `libgomp1`이 없으면 LightGBM이 로드되지 않는다(`sudo apt-get install libgomp1`).
- v1을 이 환경에서 다시 실행해 모든 연도·기준선 MAE가 원본과 비트 단위로 일치함을 확인했다.
- 사전 등록 문서의 SHA-256은 저장소에 저장된 내용(LF 줄바꿈) 기준이다. Windows에서 autocrlf로 받은 작업 파일은 CRLF가 되어 해시가 다르게 나오므로 `git show HEAD:<경로> | sha256sum`으로 확인한다.
- 지역 재표집 95% 구간은 `metrics.paired_region_bootstrap`이 지역 순서를 고정하지 않아 실행마다 수십 명/일 흔들린다. 0 포함 여부는 재실행에서 같았다.
