# 2차 리서치 종합 — "검증이 데이터 안에서 끝나는" 주제로 다시 고름

> 2026-08-18. 원자료: `01_데이터_인벤토리.md`, `02_여행자관점_예측형_후보8.md`, `03_역대_학생수상작_실체_벤치마크.md`, `04_사업자관점_수요예보_후보8.md`
> 1차 리서치(축제 검증·오버투어리즘·VOC 등)는 "사용자가 지자체 / 검증이 시뮬레이션 / 왜 하는지 모호"라서 폐기.

## 1. 이번에 확실해진 사실 3가지

**① "검증"은 예측 문제를 고르면 저절로 해결된다.**
역대 학생 수상팀(2022~2025)은 전부 우수상 이하였고, 증거는 설문 288명(KAIST), 회귀 추정치(에이블스쿨, 앱은 UX 설계만), 시사점 4개(성균관대), 웹 데모 캡처(DScover)가 전부였다. 대상·최우수는 항상 실측 숫자를 가진 기관. → 학생팀 현실 목표는 **우수상(6팀)~최우수(2팀)**, 차별화는 **"실측 숫자 하나"** — 예측 문제면 **백테스트 정확도(MAPE·적중률)가 그 실측 숫자**가 된다. 설문·시뮬레이션에 기대지 않아도 됨.

**② 로그인 없이 지금 받을 수 있는 건 사실상 하나뿐 — 시군구 일단위 방문자(2018~).**
- data.go.kr API 15101972: 시도/시군구 × 일 × 현지인/외지인/외국인 방문자, KT 2018~, SKT 외국인 2020~. 개발계정 1,000건/일.
- 그 외 데이터랩 데이터(신한카드 소비, TMAP 검색, 성/연령, 유입유출, 숙박·체류, 국적별)는 **회원가입(무료·이메일) 후 수동 CSV**. 공식 API 없음, 스크래핑 금지 고지. 빅데이터 원자료 메뉴에 **일간 옵션**이 있음(카드·TMAP 일단위 CSV 가능성 → 로그인 후 확인).
- **시간대(hourly) 데이터는 어디에도 없음. POI 일별 실측도 없음.** 있는 건 KTO 자체 "관광지 집중률 향후 30일 예측"(POI, 상대치)뿐.
- 보완: 기상청 단기·중기예보 API, 공휴일 API, TourAPI(운영시간·쉬는날 필드 확인됨), 문체부 축제정보(예산·방문객), 주요관광지점 입장객(월).

**③ 데이터랩은 이미 "방문자 예측"을 한다.** (지역별 관광현황 대시보드 5주 예측 + POI 30일 집중률 API)
→ "다음 주 방문객 몇 명" 자체는 창의 0점. 우리가 예측해야 하는 건 데이터랩이 안 하는 것: **구성(외지인/외국인 국적/연령), 날씨 탄력, 가격 기준선, 대체지, 그리고 그걸 누군가의 결정(발주·알바·요금·날짜 변경)으로 번역한 것.** 데이터랩 예측은 이겨야 할 baseline으로 쓴다.

## 2. 최종 후보 5 (같은 잣대: 왜 한 줄 / 정확히 무엇을 예측 / 검증 / 첫 주 실체)

### ★ A. "우리 동네 관광수요 예보" — 관광지 소상공인용 (외지인·외국인 구성 → 발주·알바·결제·다국어)
- **왜 한 줄**: 데이터랩은 5주 예측까지 만들어놨지만 그걸 읽어서 장사에 쓰는 상인은 없고(디지털 도입 27%), KTO 데이터마케팅 컨설팅은 **연 27개사**뿐. 캐시노트·스마트플레이스·소상공인365는 내 가게 과거 매출/행정동 유동인구만 보여주고, **"다음 주 우리 동네에 외지인·외국인이 얼마나·어디서·어느 국적으로 오는지"는 데이터랩만 안다.**
- **정확히 예측**: (a) 시군구 일단위 **외지인 방문자 D+1~D+7** (b) 월 **외국인 소비 국적별 비중** 1~2개월 선행 (c) 축제·연휴 급증일 이진. 피처: 요일·공휴일·연휴 길이·기상예보·축제 일정·TMAP 검색·국적별 입국·외국 연휴(골든위크·노동절·국경절)·크루즈 입항.
- **검증(실측 숫자)**: rolling-origin 백테스트 2023~2025 — 7일 MAPE, 급증일 F1, **naive(전년 동요일)·데이터랩 자체 5주 예측 대비 개선 %p**. + 매주 자동 "지난 예보 채점" 로그(서비스가 스스로 검증). + 상인 5~10명 4주 시범(브리핑 이해도·실행 항목 수).
- **실체**: 일요일 저녁 카톡 "이번 주 외지인 지수 128(전주 100) · 토요일 급증 82% · 수도권·20대 여성↑ · 대만 관광객 다음 달 +35% → 발주 1.2배 / 토 알바 +1 / 번체 메뉴·유니온페이 준비". 웹: 가게 위치·업종 입력 → 7일 카드 + 근거(축제·연휴·날씨) + 적중 기록. 심사위원이 "경주 황리단길 카페" 입력하면 즉석 재실행.
- **근거**: 외식 인건비 비중 30.9%·76.3% 애로, 음식서비스 미충원 1.5만(헤럴드 2026); 부산 1~5월 외국인 +40%, 서산 크루즈 첫 입항 시 편의점 중국인 매출 96배, GS25 알리·위챗 부산 연제 10배(머니투데이 2026-07-15), 강릉 외국인 결제 +300%; 전주 한옥마을 822점포(소진공 관광형 상권 육성 2026.05).
- **데이터랩 사용**: 이동통신 일단위(API) + 신한카드 현지인/외지인/외국인·업종(CSV) + 외래객 국적별 방한현황 + 성/연령 + TMAP 검색 + 축제 현황 + 유입유출 + 인구감소지역 (7~8종). 슬로건 "Real Biz Solution" 정중앙.
- **리스크**: 상인 섭외(부모님·지인 가게, 팀원 알바처, 상인회로 5~10명이면 충분). 신한카드 국적×시군구×업종 해상도 로그인 후 확인. 데이터 lag(KT 4일 전) → "예보"가 nowcast가 안 되게 D+7 예측으로 설계.
- **차별화 대비 경쟁**: 제주 로컬타임 AI(2026.8 대상)는 실시간 재고 매칭 마켓플레이스 → 예측·백테스트·국적 구성 아님. 네이버 Agent N은 내 가게 데이터.
- **성과분야**: 앱·웹 등 서비스 개발 (또는 매출·수익). **배점 예상: 창의 7 / 데이터 9 / 성과 8 / 파급 8 = 82**

### B. "비 오면 이 여행 망하나?" — 지역별 우천 탄력도 판정 + 플랜B
- **왜 한 줄**: 주말 비 예보에 "갈까 미룰까"를 결정할 근거가 없다. 해변형 지역은 비 오면 방문 −45%, 도시형은 −8% — 지역마다 다른데 아무도 안 알려줌.
- **예측**: 시군구별 강수량 대비 방문자 감소율(2018~ 일단위 방문자 × 기상청 ASOS) → 특정 날짜 강수 시 예상 감소 %, "취약일" 이진. 백테스트 2024~25 강수일 MAPE·AUC.
- **실체**: 목적지 → 우천 탄력도 게이지 → 비 예보 결합 "미룰까/갈까" 판정 → 우천 둔감 대체 시군구·실내 POI(TourAPI) 플랜B.
- **장점**: **100% 로그인 없는 데이터로 완성 가능**, 가장 창의적, 6주 중 가장 쉬움. **단점**: 데이터랩 1종만 쓰면 데이터활용 30점 약함 → 유사지역·관광지별·소비 데이터로 보강 필요. 왜가 "간지러운" 편.
- **배점 예상: 9 / 7 / 7 / 7 = 74**

### C. "이번 주말 강릉 얼마나 붐벼? 대신 어디?" — 시군구 혼잡 예보 + 대체지
- **왜 한 줄**: 20~30대 나들이 부담 1위가 인파 혼잡 37.9%(PMI 2026.04). 구석구석·지도앱은 '지금' 혼잡만, 미래 날짜는 없음.
- **예측**: 시군구 외지인 일 방문자 D+1~D+14·상위 10% 혼잡일. **KTO 집중률 API를 baseline으로 이긴 %p 보고.** 유사지역 탭으로 한산 대체지 3곳.
- **리스크**: 데이터랩이 이미 예측함 → "왜 또?"에 답해야(절대치·대체지·날씨·D+14 이상). AI 플래너로 미끄러지기 쉬움. **배점 예상: 6 / 9 / 8 / 7 = 77** (창의 방어 실패 시 급락)

### D. "이 숙박비 성수기 값이야 바가지야?" — 시군구 숙박·외식 물가지수 예보
- **왜 한 줄**: 국내여행 외면 1위 이유 = 관광지 물가 45.1%(한경협 2025.07), 정부 바가지 근절대책(2026.02). 야놀자·여기어때는 매물가만, "이 지역이 지금 비싼 시기인가" 기준선 없음.
- **예측**: 신한카드 시군구×업종(숙박·음식) 외지인 **건당 소비단가** 월 예측 + 계절지수 → 입력 가격 백분위 판정.
- **리스크(큰)**: 카드 건당 단가 ≠ 1박 요금(결제 건 기준, 더치페이·복수 인원). "바가지" 판정을 KTO 심사위원 앞에서 카드 데이터로 주장하면 반박 위험. 건수 데이터 제공 여부 미확인. **배점 예상: 8 / 8 / 6 / 8 = 74**

### E. "붐비기 전에 가야 해?" — 검색→방문 선행지표로 뜨는 소도시 탐지
- **왜 한 줄**: 인제 +40.3%·영월 +21.4% 소도시 급증(데이터랩 2027 트렌드), Z세대 '남들 안 가는 곳'. 트리플 '급상승'은 자사 로그·사후.
- **예측**: 시군구 월 방문자 다음 달 전년비 증가율 상위 10% 진입(이진). 입력 TMAP 검색·내비·카드 증가율. precision@10, 검색→방문 lag 검증.
- **리스크**: TMAP 관광지·월 단위, 트렌드 케이스 적어 검증 분산 큼. Local Growth 정합은 좋음. **배점 예상: 9 / 9 / 6 / 8 = 77** (성과 입증 약함)

## 3. 추천과 헤지

**추천: A (소상공인 관광수요 예보).** 이유: 심사위원(KTO 데이터허브팀)이 만든 데이터의 "마지막 1마일"을 채우는 이야기라 왜가 선명하고, 데이터랩 종수·슬로건·파급 모두 최고, 검증은 백테스트+주간 자동 채점+상인 시범 3중.

**헤지 (권장 실행 구조)**: A·B·C는 **같은 엔진**(시군구 일단위 외지인 방문 예측 + 날씨 + 축제 + 연휴)을 쓴다.
- 1~2주차: 엔진부터 만든다 (API 벌크 수집 → 피처 → LightGBM/Prophet → 백테스트 수치). 이건 어느 얼굴을 고르든 필요.
- 2주차 말: 상인 5명 섭외 성공 여부로 얼굴 결정 → 성공하면 A, 실패하면 B(우천)+C(혼잡·대체지)를 여행자용 하나로 합침("이번 주말 어디, 비 오면?").
- 3주차부터 얼굴(웹+에이전트+카톡) 개발, 5주차 시범, 6주차 서식4.

## 4. 이번 주 할 일 (실체가 보이게)
1. data.go.kr 계정 → 15101972·15128555·TourAPI·기상청·공휴일 키 발급, 시군구 일단위 방문자 2018~현재 벌크 수집(1,000건/일 한도 → 3~4일에 나눠서 or 운영계정 신청).
2. 데이터랩 회원가입 → 빅데이터 원자료 메뉴 **일간 옵션** 확인(신한카드·TMAP), 외래객 국적별 시군구 CSV, 신한카드 외국인 소비 국적 해상도 확인.
3. 노트북 하나: 강릉·경주·전주 3개 시군구 외지인 일 방문자 그래프 + naive 예측 vs 간단 모델 MAPE. **이 숫자가 나오는 순간 "검증 못 하겠다"는 걱정은 끝난다.**
4. 상인 섭외 리스트 5명 (부모님·지인·알바처·상인회) — 연락만.
