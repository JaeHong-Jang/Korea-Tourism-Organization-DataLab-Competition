# T-308 시나리오 평가 실행과 채점 조건

`scenarios.jsonl`의 고정 기대값으로 실제 게이트웨이 SSE를 채점한다. 실행 결과로 정답을 만들지 않는다. 기존 추출 30건 평가는 `run-extract-eval.ts`로 별도 실행한다.

```bash
npm -w services/gateway run eval:scenario -- --fake
npm -w services/gateway run eval:scenario -- --base http://127.0.0.1:8787 --out reports/evals/scenario-2026-09-25.json
```

두 명령 모두 JSON과 같은 이름의 Markdown을 쓴다. `--out`은 확장자 없는 이름, `.json`, `.md`, `.{json,md}`를 받는다. 상대 경로는 저장소 루트 기준이다. 가짜 기본 파일은 `reports/evals/scenario-<KST 날짜>-fake.{json,md}`로 실제 평가 파일과 구별된다. 실패 시에도 전체 사례를 끝까지 기록하고 종료 코드 1을 반환한다. 잘못된 옵션·사례 정의는 실행 전에 거부한다.

실제 실행은 forecast·knowledge·records·Ollama에 연결된 게이트웨이가 이미 떠 있어야 한다. 워커 샌드박스의 소켓 제한 때문에 실제 실행과 기존 HTTP 테스트는 오케스트레이터가 수행한다. 실행기는 서비스를 시작하거나 모델을 적재·해제하지 않는다. `node --import tsx`는 CLI의 IPC 소켓 없이 같은 TypeScript 실행기를 사용한다.

- 새 예보 12건: 유형 6종. 폭죽·수면 위험 2건은 이 12건에 포함한다. 추가로 필수값 누락 3건, 발행 세션의 후속 3건, 같은 세션의 범위 밖 2건으로 총 20건이다. 부산 불꽃 사례는 위험 확인에 빈 배열로 답하는 경우다.
- JSONL의 `{{date}}`는 실행일 KST + `offsetDays`(3~13일)로 바꾼다. 실제 행사 일정이 아닌 가상 요청이다. 인천 개편 지역은 사용하지 않는다. 시작일이 2026-10-18 이상이면 자료 조건 재검토가 필요하므로 실행을 중단한다.
- 첫 메시지는 자연어를 그대로 보낸다. `answer`가 있는 위험 확인 사례만 같은 세션에서 한 번 답한다. 예상 밖의 필수값을 자동으로 채우지 않는다. 필수값 누락 사례는 질문 수신에서 끝낸다.
- 순서는 요청마다 계약의 `sequenceProblems`에 `new` 또는 기존 카드 id가 있는 `followup` 문맥을 준다. 저장·초안의 `done.forecastId`는 기존 예보를 가리키며 새 문장 발행으로 세지 않는다.
- 근거 연결은 각 요청에서 보낸 `evidence.items`만 인정한다. 숫자 검산은 생산 코드의 `checkNumbers`·`formatQuantity`·검사 통과 플래그를 사용하지 않는다. `rendered` 숫자와 원문 자리표시자의 위치·단위·Quantity 필드·인용 근거의 `quantityIds`를 독립 비교한다. 정수 인원 반올림을 허용하고 숫자 바꿔치기·삽입·미등록 참조를 거부한다. 인용한 규칙의 완전한 문구만 리터럴 숫자 예외다. 규칙 요약 뒤 `입력:` JSON은 예외가 아니다.
- 카드에는 `basis`가 없어 발행 후 `GET /api/forecasts/{id}`의 예보서를 읽는다. 카드 Quantity도 저장 예보서와 대조한다. `basis=구간`이면 발행 문장·카드 판정 문구·확률 표시의 `%`를 거부한다. 후속은 앞선 실제 스트림 카드와 예보서를 재사용하되 근거는 이번 요청에서 다시 받아야 한다.
- 지연은 POST 직전부터 프레임 수신까지 `performance.now()`로 측정한다. 되묻기가 기대되거나 발생한 사례는 왕복 제외를 위해 지연 분포에서 제외한다. 나머지 새 예보는 카드·발행 done, why는 발행 done을 집계한다. 저장·초안·범위 밖·무발행 완료는 발행 지연에서 제외한다. 세션 생성·예보서 조회·모델 상태 조회는 지연에 포함하지 않는다. 원시 턴별 시각은 JSON에 모두 남긴다. p50·p95는 최근접 순위다.
- LLM 수는 `agent_step.usedLlm=true`인 단계 수다. 단계 내부 재시도 횟수는 SSE 계약에 없으므로 실제 HTTP 호출 횟수와 같다고 단정하지 않는다. 모델명은 해당 단계에서 관측한다. Ollama 적재 여부는 시작·종료의 `/api/health` → `/api/ps`로 확인하며 접근 실패는 `확인 불가`로 기록한다.
- 가짜 모드는 메모리 서비스와 계약 기반 픽스처를 실제 상담 라우트에 주입하고 같은 SSE 리더·채점기를 사용한다. forecast 수치는 게이트웨이의 계약 기반 `fixtures/services/forecast.json`, 평시는 계약 `region-baseline` 픽스처다. 사례별 식별자·날짜·지역 메타데이터만 연결한다. knowledge는 계약 참조·수명 주기와 일부 게이트 검사를 재현하며 SHACL 전체 구현은 아니다. LLM 녹화 응답 실패는 실제 템플릿 경로로 처리한다. 가짜 스트림은 평가 JSON에 보존하고 공용 traces에는 쓰지 않는다.
