# T-living-city 결과: DONE

현재 연속형 미니 대한민국 지도에 기존 축제 시설과 사람·교통 모델을 연결했다. 축제 시설은 선택한 행사 위치 주변의 빈 공간에 배치하고, 도시 보행·교통은 카메라가 보여 주는 지역을 기준으로 관리한다. 예보 수치는 변경하지 않았다. 커밋·푸시는 하지 않았다.

## 재사용과 변경

| 요소 | 이전 상태 | 이번 연결 |
| --- | --- | --- |
| 무대·부스·입구·휴게 시설·가랜드 | `regional-diorama`에 존재했으나 현재 지도에 미연결 | 실제 지형 고도와 건물·도로·수면 검사를 적용해 정적 메시로 병합 |
| 관람객 외형·걷기·색종이 | 별도 지역 장면용 | 무대 관람·부스 대기·휴식 목적지, 소규모 일행, 간격 유지, 교착 시 다음 목적지 선택 |
| 승용차·택시·버스 | 공용 `vehicle-kit`에 부품 모델 존재 | 실제 도로의 연결 그래프, 가능한 일방통행 정보, 차간 감속, 교차로 양보·버스 정차 연출 |
| 기차 | 기존 지도에서 선형 경로를 왕복 | 실제 철도 그래프와 지나온 궤적을 사용해 세 객차 연결 |
| 배·비행기 | 이전 전국 연출 모델과 항구·공항 연결선 존재 | 모델 재사용, 화면 범위별 활성화, 배의 육지 통과 구간 제외, 비행 고도 유지 |
| 불꽃 | 기존 야간 입자 효과 존재 | 불꽃 유형의 야간 행사에서만 18초 중 5초 사용, 모션 줄이기 시 제외 |

안내소와 꽃 행사 화단을 추가했다. 축제 유형에 따라 시설 수와 무대·화단 구성이 달라진다. 무대 전면과 부스 간격, 기존 보행로를 비운다. 시설 네 모서리의 높이 차이가 1.8m를 넘으면 해당 자리를 사용하지 않는다. 공간이 부족한 행사에서는 시설 수를 줄인다. 강남 화면에서 10개, 세종한글축제에서 28개 시설을 확인했다.

선택 시 지도 폭을 기존 3.2km에서 1.2km로 변경해 축제 시설을 더 가까이 보여 준다. 행사 좌표·위치 점·연결선·행정구역 경계·지형·건물 형상은 유지했다. 전국 보기와 예보 상담 이동을 브라우저에서 확인했다.

## 화면 범위와 비용

- 경위도 화면 경계를 투영하고 15% 여유 영역을 둔다. 계속 보이는 객체는 좌표에서 만든 경로 ID와 이동 상태를 유지한다.
- 도로 연결·보행 충돌 검사를 별도 `activity-worker`로 옮겼다. 작은 이동은 기존 계산 범위를 재사용하고 처리 중에는 최신 요청 하나만 대기시킨다.
- 원본 지도 데이터는 바뀔 때만 작업 스레드에 전달한다. 위치만 바뀌면 작은 화면 경계 정보만 전달한다.
- 전국 화면에서는 작은 객체를 시뮬레이션하지 않는다. 넓은 지역에서는 간선 도로를 우선하고 상세 차량 부품을 생략한다.
- 기본 고품질 상한은 차량 180대, 거리 보행자 640명, 열차 6편성, 비행기 6대, 배 10척이다. 실제 수는 화면·경로·기기 품질에 따라 감소한다. 축제 관람객은 별도로 최대 360명이다.
- 같은 모델은 인스턴싱한다. 차량의 색·차종과 보행자의 옷 색은 생성 ID에 고정한다. 시설은 하나의 메시, 부스 야간 등은 하나의 인스턴스 메시로 그린다.
- 시설 배치 캐시는 3개 행사로 제한하고, 지도 원본 캐시는 기존 80타일 제한을 유지한다. 객체는 화면 여유 영역 밖에서 제거한다. 이벤트·타이머·작업 스레드는 장면 해제 시 정리한다.
- 비활성 상태 신호와 모션 줄이기에서 이동 정지를 확인했다.

## 실제 자료와 연출의 구분

도로·철도·건물·수면은 프로젝트의 로컬 OSM 지도 자료를 사용한다. 보행로 정보가 없는 곳에서는 도로 바깥쪽 후보를 만들고 건물·수면·차도와 교차하는 후보는 제외한다. 보도 폭과 모든 횡단보도를 실측한 자료는 아니다.

시설 배치는 공식 행사 배치도가 아니며, 사람 수와 행동·교통 흐름·양보 주기는 연출이다. 배와 비행기는 기존 항구·공항 연결 연출을 재사용했다. 배 경로는 국토 형상과 충돌하는 구간을 제외하지만 공식 항해 항로나 실시간 운항 데이터가 아니다. 항공기 이착륙·활주로 절차는 구현하지 않았다.

범례와 모바일 안내에 실제 배치·실시간 운행·예측 인원이 아니라는 설명을 표시했다. 도시 연출 인형 수를 실제 예보 인원으로 환산하지 않는다.

## 검증

- `npm.cmd --workspace apps/web test`: 87개 파일, 366개 테스트 통과.
- 최종 변경 후 관련 경로·시설·보행 테스트: 5개 파일, 17개 테스트 통과.
- `npm.cmd --workspace apps/web run build`: 타입 검사와 Vite 빌드 통과. 기존 대형 번들 경고는 남아 있다.
- Edge 실제 WebGL 브라우저: 강남·세종 축제, 낮·밤 전환, 서울역 철도, 부산 해안, 김포공항, 설악산 지역, 연속 카메라 조작, 전국 복귀, 예보 상담 이동 확인. 페이지 실행 오류 없음.
- 작은 화면 이동에서 기존 차량 152대 중 152대 유지, 관람객 이동 상태 객체 유지.
- 8초 연속 이동·회전·확대: 약 60.1FPS, 프레임 간격 중앙값 16.6ms, p95 18.5ms. 측정 중 기존 차량의 최대 프레임 간 이동은 0.323m였다.
- 부산 앞바다의 이동 선박 위치 242개 표본에서 국토 내부 판정 0건. 모든 해안·모든 시점에 대한 증명은 아니다.
- 지역 진입·전국 복귀 4회: 전국 화면 지오메트리 38개, 텍스처 1개, `visibilitychange` 리스너 2개로 유지. 강제 GC 후 메인 스레드 JS 힙은 358.5 → 362.5 → 362.7 → 362.8MiB였다. GPU·작업 스레드 메모리를 포함한 전체 메모리 측정은 아니다.

동일한 Intel 내장 그래픽, Edge, 1600×1000, DPR 1, 서울 도심 지도 폭 3.2km에서 로딩 완료 후 5초간 같은 카메라 이동으로 비교했다. 기본 선택 화면은 1.2km지만 비교 측정에서는 3.2km를 강제로 맞췄다. 프레임 시간은 렌더 콜백 간격이며 CPU/GPU 작업 시간을 따로 측정한 수치는 아니다.

## 남은 한계

- 도로 연결·차선·신호·교통량·열차 시간표·공식 항로의 완전한 교통 시뮬레이터는 아니다. 일방통행 정보가 없는 도로는 양방향으로 취급한다. 연결 정보가 끊긴 구간에서는 이동을 멈추거나 존재하는 역방향으로 돌아간다.
- 지형은 기존 약 500m 고도 격자를 사용한다. 개별 교량·계단·경사로 높이를 정확히 재현하지는 않는다.
- 원본 보행로·건물·수면 자료가 부족한 지역에서는 활동 또는 시설이 적을 수 있다. 실제 위치를 옮겨 빈자리를 만들지는 않는다.
- 시설 배치를 관찰한 행사는 강남·세종이며 모든 축제장의 배치를 수동 검수한 것은 아니다. 일반 규칙은 전체 행사에 적용된다.
- 검증 스크립트·측정 JSON·스크린샷은 `.cache/check-living-city.mjs`, `.cache/check-city-resources.mjs`, `.cache/check-city-motion.mjs`, `.cache/profile-city-final.mjs`, `.cache/living-city-*.png`에 남겼다.

변경 파일은 `national-map/activity/`의 기능별 모듈, 지도 작업 스레드 데이터 연결, 기존 지역 축제 구현, 공용 차량 부품, 범례와 지도 페이지이다. 외부 의존성과 계약 변경 없음. BLOCKED 없음.
