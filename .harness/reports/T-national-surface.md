# 전국 지형·축제 위치·성능 수정

- 원인: 시군구 ExtrudeGeometry의 2.5km 옆면에 DEM을 얹어 행정구역 절벽과 섬 기둥이 생김. 전국 토지 피복에도 최대 1.2km 분할을 적용해 색면만 약 468만 삼각형을 생성함.
- 수정: 윗면만 생성해 실제 DEM을 적용. 색면 분할은 화면 폭/320, 60m~8km로 제한. 확대 지역은 세밀한 표본을 유지. 실제 해안선·섬·축제 좌표는 변경하지 않음.
- 위치 표시: 이름표 묶음과 무관하게 모든 행사 211개의 실제 좌표에 지형을 따르는 원. 1회 병합 렌더링, 축척 단계 캐시, 이전 버퍼 dispose. hover 이름·click 확대. 같은 좌표는 이동하지 않으며 실제 행사 면적과 다른 위치 표식임을 범례에 표시.
- 지형과 도시 활동의 렌더 순서 수정은 기존 작업을 포함하며 시설·보행·교통 구현과 함께 보존함.

## 측정

2026-09-29 로컬 Edge headless, 1600×1000, 같은 브라우저·기기·초기 구도, 지도 로딩 후 7초 대기, 카메라 이동·회전·확대를 8초 실행. 자동 품질, DPR 1. 콜드 다운로드 비교는 아님.

| 측정 | 수정 전 | 수정 후 |
|---|---:|---:|
| FPS | 11.95 | 60.06 |
| 중앙 프레임 시간 | 85.8ms | 16.7ms |
| p95 | 116.5ms | 17.0ms |
| 최대 프레임 시간 | 275.5ms | 27.0ms |
| 50ms 초과 프레임 | 88 | 0 |
| 삼각형 | 5,912,518 | 995,349 |
| 드로우콜 | 19 | 20 |
| JS heap 샘플 | 875,244,548B | 290,515,325B |

수정 전 자동 품질은 medium까지 하락했고 수정 후 high를 유지했다. Heap은 GC를 강제하지 않은 시점 샘플이며 전체 GPU·Worker 메모리가 아니다. 중간 단계의 옆면 제거만으로는 17FPS에 그쳐 색면 세분화 수정이 필요함을 확인했다.

## 검증

- 웹 TypeScript 및 Vite build 성공(기존 번들 크기 경고 유지).
- 지도·지형·축제 회귀 테스트 14파일 48개 통과.
- 커밋 대상만 별도 폴더에 복사한 상태에서도 웹 빌드와 지도 전체 테스트 32파일 113개 통과. 관계없는 작업 트리 변경에 의존하지 않음을 확인.
- 실제 브라우저 전국/남해/제주/아티언스 지역 확인. 지형 바닥 정점 없음, 축제 원 211개, 원 선택 후 1.2km 확대, 전국 복귀 성공, pageerror 없음.
- 도심 8초 연속 조작: 60.05FPS, 중앙16.7ms, p95 19ms. 같은 차량 프레임 이동 최대0.323m, 해안 배 242표본 중 육지 통과0회.
- 측정 스크립트·상세 출력: `.cache/check-national-surface.mjs`, `.cache/national-surface-{before,after}.json`, `.cache/check-ground-rings.mjs`, `.cache/ground-rings-validation.json`, `.cache/check-city-motion.mjs` (로컬 진단 산출물).

## 한계

- 전국에서 색면의 고도 표본을 성기게 하므로 작은 지형 굴곡의 음영은 단순해진다. 지역 확대의 건물 형태·높이와 DEM 원본은 유지한다.
- 한 기기에서 확인한 결과이며 모든 기기의 무끊김을 보장하지 않는다. 상세 타일 첫 로딩은 별도 비용이 남는다.
- 전국 상세 PMTiles 큰 파일은 별도 공유 대상이며 기존 저장소 공유 타일·새 DEM 소형 자료를 사용한다.
