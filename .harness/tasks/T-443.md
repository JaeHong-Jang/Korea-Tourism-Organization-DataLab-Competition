# T-443: 축제 대표 이미지 — TourAPI firstimage를 로컬에 받아 두고 `/v1/images/{eventId}`·festival-summary `image`로 제공

- 사용자 요청(9/25 밤): "각 축제 이미지 같은 거 좀 들어가는 게 좋지 않아?"
- 읽을 것: services/forecast/src/crowdcast/data/(TourAPI 클라이언트·행사 마스터 보강 — `firstimage`/`firstimage2` 필드가 응답에 있는지, 공공누리 유형 필드), services/forecast/src/crowdcast/{analytics/upcoming.py, api/routes/upcoming.py}, packages/contracts/{schemas/festival-summary.schema.json(`image` — url은 `/api/images/<eventId>`, credit 필수), openapi/forecast.yaml(`/v1/images/{eventId}`)}, 공유 호출 장부 규칙(`data/cache/datago/ledger.csv`), AGENTS.md §3·§5
- 허용 경로: `services/forecast/src/crowdcast/data/`(이미지 URL 보존·받기 CLI), `services/forecast/src/crowdcast/api/routes/images.py`(새)·`api/app.py`(등록 줄만), `services/forecast/src/crowdcast/analytics/upcoming.py`·`api/routes/upcoming.py`(summary `image` 붙이기), `services/forecast/tests/`
- 인터페이스:
  - **URL 보존**: TourAPI 보강 때 `firstimage`(없으면 `firstimage2`)와 저작권 유형(`cpyrhtDivCd` 등 응답에 있는 것)을 행사 마스터에 보존(새 열, 없으면 null).
  - **받기 CLI**: `python -m crowdcast.data.images fetch --upcoming` — 다가오는 일괄 예보 행사만, 이미 받은 것 건너뜀, 요청 간격·총량 제한(설정), `data/cache/images/<eventId>.<ext>`(원본 확장자·Content-Type 확인, 5MB 넘으면 건너뜀) + `index.json`(eventId → 파일·원본 URL·저작권·받은 시각·sha256). 이미지 파일은 data.go.kr API 호출이 아니지만 **외부 요청 수를 장부와 따로 기록**한다.
  - **제공**: `GET /v1/images/{eventId}` → 캐시 파일 그대로(Content-Type·`Cache-Control: max-age=86400`), 없으면 404(외부 호출 없음). 다가오는 행사 목록(`/v1/festivals/upcoming`)의 summary에 캐시가 있으면 `image: {url: "/api/images/<eventId>", credit: "한국관광공사 TourAPI · <공공누리 유형>"}`(없으면 필드 생략 — 일괄 예보 파일은 바꾸지 않고 응답 때 붙인다).
- 수용 기준: `pytest -q services/forecast/tests`·ruff, 테스트: URL 보존(픽스처 응답), 받기 CLI(MockTransport — 건너뜀·크기 제한·index), 라우트(200·404·Content-Type), summary `image` 계약 검증·캐시 없으면 생략. **실제 받기는 오케스트레이터가 9/26 TourAPI 보강 뒤**.
