## 게이트 피드백 1회차 (PARTIAL + 오케스트레이터 게이트 4 — 스크린샷 직접 확인) — 워크트리에 결과가 있다
**해소된 BLOCKED**: 경계 링크 `apps/web/public/geo/sigungu.topo.json`을 오케스트레이터가 워크트리에 만들었다(`worktree.sh`도 고침). 일반 실행 경로로 다시 확인한다.
1. [High, 화면] **렌더링 결함** — 세 스크린샷 모두 땅·바다·판 위에 가로 줄무늬가 있고(같은 높이 면 겹침 z-fighting 또는 그림자 acne), 오른쪽 위에 바다가 덮지 않은 갈색 삼각형이 보인다. 땅이 매끈한 장난감 타일이 아니라 거칠다. → 판 윗면·바다·땅 높이를 분리(예: 판 0, 바다 +0.2, 땅 +0.5~1.0 단위), 바다 판이 나무판 윗면을 빈틈없이 덮게, 그림자 bias·normalBias 조정 또는 그림자 끔(품질 low/medium), `logarithmicDepthBuffer` 대신 near/far를 장면 크기에 맞춤. 땅은 `flatShading` 없이 부드러운 법선, 윗면 한 색(시군구마다 번갈아)과 옆면 약간 어둡게.
2. [High, 화면] 대비 — 낮에는 땅과 바다 색이 비슷해 한반도가 흐리고, 밤에는 거의 안 보인다. → 땅(`--scene-land-*`)과 바다(`--scene-sea`) 명도 차를 키우도록 조명·노출(toneMapping)을 조정하고, 밤에는 HemisphereLight를 낮게라도 유지해 땅 윤곽이 보이게(04 §9 — 밤은 "어둡지만 읽히는" 장면). 판 가장자리 둥근 모서리도 보이게.
3. [Med] 노을 강제 — 18:20은 실제 해 고도 −6.3°라 테마 엔진 규칙상 밤이다. 장면만 노을로 바꾸면 헤더("밤")와 어긋난다 → 장면 전용 노을 강제를 지우고, 노을 스크린샷은 **실제로 노을인 시각**(예: `2025-10-18T18:00+09:00`, 해 고도 −6°~6° 안인지 확인)으로 찍는다.
4. [Med] 성능 측정 — 렌더러를 기록하지 않았다. 헤드리스 크로미움은 보통 소프트웨어 렌더러(SwiftShader)라 p50 36ms가 실제 GPU 성능이 아닐 수 있다 → `WEBGL_debug_renderer_info`로 렌더러 문자열을 결과에 기록하고, 가능하면 GPU 가속(`--use-gl=angle`·`--enable-gpu`·headed)으로 다시 잰다(안 되면 소프트웨어 렌더러임을 명시). **Ollama 동시 측정**: Ollama는 WSL 기본 게이트웨이 주소에 떠 있다 — `scripts/dev.mjs`와 같은 순서(.env `OLLAMA_HOST` → WSL 게이트웨이 → 127.0.0.1)로 찾아서 받아쓰기 모델(`OLLAMA_MODEL_FAST`)로 10회 연속 요청하며 잰다.
5. [Med, CONTRACT-CHANGE 승인] 시군구 선택: `apps/web/src/lib/selection-store.ts`에 `selectedSigunguCode`와 `selectSigungu(code|null)` **추가만** 허용(기존 필드·동작은 바꾸지 않는다 — L4a 소유 파일). 장면 클릭 → `selectSigungu`.
6. [Low] 3D 장면 안 명세 코드("M1-F1 · 전국 판" 등)는 T-402가 숨기는 중이니 이 task에서 건드리지 않는다.
- 스크린샷 3장을 다시 찍고, 리포트에 줄무늬가 사라졌는지 확대 비교(같은 영역 크롭) 한 줄.
