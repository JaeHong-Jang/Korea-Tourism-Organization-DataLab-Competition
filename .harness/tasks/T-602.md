- 읽을 것: docs/plan/09 §0(SHACL은 구조만)·§1(검증 범위)·§2(IRI)·§5(S01~S12)·§7(발행 상태)·§10(API), packages/contracts/schemas/gate-report.schema.json, packages/contracts/openapi/knowledge.yaml, services/knowledge(T-601 결과)

- 인터페이스:
  - `POST /v1/sessions/{id}/validate?revision=&masterVersion=&shapes=` → 계약 `gate-report`(검사한 revision·masterVersion 기록). 검증 입력 = 해당 세션 named graph의 그 revision 스냅샷 + 그 masterVersion의 기준 그래프 + TBox. revision이나 masterVersion이 현재와 다르면 409
  - `POST /v1/sessions/{id}/publish?revision=&masterVersion=` → S12 통과 시 `cc:status "candidate"` → `"published"`를 한 트랜잭션으로 바꾸고 `gate-report`(새 revision) 반환. 실패면 위반 목록, 범위가 바뀌었으면 409
  - pySHACL `advanced=True`(SHACL-SPARQL 사용: S09·S12)
- 수용 기준(실행 명령):
  - `uv run --package crowdcast-knowledge pytest -q services/knowledge/tests` 통과: 규칙마다 **정상 그래프 통과 + 위반 픽스처 거부**(S09는 관측값 누락·날짜 형식 오류·미래 공개일·다른 행사 관측값 4종), revision 불일치·masterVersion 불일치 시 validate·publish 409, gate-report 응답이 계약 스키마 통과
  - 정상 그래프는 계약 픽스처(`fixtures/forecast/valid-yeongjong.json`, `fixtures/claim/valid-published.json`을 candidate로 바꾼 것)를 T-601 변환으로 적재해 만든다(손으로 쓴 TTL만으로 통과시키지 않는다)
  - 검증 시간: 세션 그래프 300트리플 기준 검증 시간을 측정해 리포트에 적는다
