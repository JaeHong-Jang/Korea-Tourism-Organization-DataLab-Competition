# T-601: 근거 그래프 서비스 골격 + 온톨로지 TTL v1 + 기준 그래프 + 세션 적재 최소판
- 레인/워커: L6 / gpt-6-astra        - 선행: R-01 통과
- 목표(한 문장): 온톨로지(09 §3~4)와 기준 그래프를 TTL로 만들고, 계약 JSON을 계약의 JSON-LD 규칙으로 RDF로 바꿔 세션 named graph에 적재(참조가 끊기면 거부)하고 revision을 올리는 최소 서비스를 만든다.
- 읽을 것: docs/plan/09 전체(특히 §1 검증 범위·§2 IRI·숫자 리터럴·적재 종류·§3 클래스·§4 속성·§6 예시·§10 API), packages/contracts/jsonld/(context.jsonld·types.json·master-ids.json·expected/), packages/contracts/check/jsonld_check.py(변환 기준 구현), packages/contracts/rules/integrity.mjs(무결성 판정 기준 구현), packages/contracts/openapi/knowledge.yaml, packages/contracts/fixtures/·fixtures-integrity/, AGENTS.md §3·§5
- 허용 경로: `services/knowledge/ontology/crowdcast.ttl`, `services/knowledge/ontology/master/` (`datasets.ttl`·`laws.ttl`·`rules.ttl`·`assumptions.ttl`·`agents.ttl`), `services/knowledge/src/knowledge/{api,store,convert}/`, `services/knowledge/tests/`
- 인터페이스:
  - `uv run --package crowdcast-knowledge uvicorn knowledge.api.app:app --port 8020`, `GET /health` → `{"status":"ok","version":"0.1.0"}`
  - IRI: 인스턴스 = `http://crowdcast.local/id/<계약 id>`(평면). 에이전트 = `id:agent-<agentId>`, 시군구 = `id:<코드 5자리>`. 세션 named graph IRI = 세션 IRI(`id:s-…`)
  - `convert.json_to_graph(obj, schema) -> rdflib.Graph`: `jsonld/types.json`의 경로 규칙으로 `@type`을 붙이고(`@include`·타입 스코프 클래스 용어 `Event`·`SimilarCase`·`RegionBaseline` 포함) `jsonld/context.jsonld`로 **pyld** `to_rdf` → rdflib. 계약 파일은 복사하지 말고 `packages/contracts/jsonld/`에서 읽는다
  - `convert.integrity_problems(obj, schema, master, scope) -> list[str]`: `packages/contracts/rules/integrity.mjs`의 `refProblems`와 **같은 판정**을 Python으로 구현한다. `master` = 기준 그래프에 실제로 있는 id + 등록된 모델 실행, `scope` = 그 세션 그래프에 이미 있는 정의(수치·근거·관측값·가정·문장·행사·예보 객체, 평시·유사 사례(자연 키), 사례 id, 지금 내용 revision — `sessionScope`와 같은 모양, 세션 그래프를 질의해 만든다). 문서 안 모든 참조 칸(`evidenceId(s)`·`quantityId(s)`·`observationIds`·`assumptionId(s)`·`caseEventId`·`claimIds`·`ruleId(s)`·`clauseId`·`datasetId`·`modelRunId`)을 풀고, 같은 id에 다른 내용이 오면 충돌로 거부한다. 문장은 충돌 대신 `rules/claim-lifecycle.mjs`의 전이 규칙(새 문장 = draft, 같은 id 재적재로 draft→candidate·→rejected, candidate 재검사 = 더 새 revision의 검사 결과로만, 동결 칸 불변, 발행은 /publish만)을 적용하고, 전이가 통과하면 세션 그래프의 그 문장을 새 상태로 **교체**한다(이전 상태 트리플을 남기지 않는다)
  - `POST /v1/sessions/{id}/facts` body `{"schema": "event"|"forecast"|"claim"|"evidence"|"similar-event"|"region-baseline", "items": [...]}` → 끊긴 참조가 하나라도 있으면 **422 + `gate-report`**(`gate: "integrity"`, 위반마다 `check: "integrity"`·노드·메시지)로 거부하고 아무것도 쓰지 않는다. 통과하면 세션 named graph에 적재, `{"revision": n}` — **내용 revision**(새 정의가 하나라도 생기면 1 증가, 문장 상태 전이·같은 내용 재적재는 그대로, 09 §1·`rules/integrity.mjs`의 `changesContent`), 세션 잠금으로 순서 보장
  - `GET /v1/master/version` → `{"masterVersion": n}`
  - 저장소: pyoxigraph `Store`(경로 `knowledge.paths.STORE` = `$CROWDCAST_DATA_ROOT/data/app/knowledge/`, 테스트는 메모리). 계약 파일은 `knowledge.paths.JSONLD`·`CONTRACTS`
  - 기준 그래프(`master/*.ttl`, 모두 `id:` 평면 IRI): `jsonld/master-ids.json`의 id를 **모두** 정의한다 — 데이터셋 14개(`cc:Dataset`, 제목·발행 기관·데이터랩 메뉴·주소; data.go.kr 주소는 docs/reference/데이터_신청_안내.md), 조항 `law-disaster-act-enf-73-9`(`cc:LegalClause`), 규칙 5개(`rule-legal-*` = `cc:LegalRule` + `cc:basedOnClause`, `rule-internal-*` = `cc:InternalRule`), 가정 8개(`cc:Assumption`, 값·범위는 docs/plan/06 §4), 에이전트 13명(`cc:TeamAgent`). 기준 그래프 버전 번호(`cc:masterVersion`) 포함
- 수용 기준(실행 명령):
  - `uv run --package crowdcast-knowledge pytest -q services/knowledge/tests` 통과:
    - TTL 전부 파싱, docs/plan/09 §6 예시 적재
    - **계약 변환 테스트**: `packages/contracts/jsonld/expected/*.json`마다 `json_to_graph(픽스처, schema)` 결과에 `triples`가 모두 있고 `absent`가 없으며 형식 오류 리터럴(`Literal.ill_typed`)이 0개(`jsonld_check.py`와 같은 판정)
    - pyoxigraph에 넣었다 꺼낸 그래프에서도 숫자 리터럴이 그대로 비교된다(`xsd:double`·`xsd:integer`)
    - `master-ids.json`의 id가 모두 기준 그래프에 있고 선언한 클래스를 가진다
    - **무결성 판정 일치**: `packages/contracts/fixtures-integrity/<schema>/*.json`마다, `fixtures-integrity/session-scope.json`의 적재 순서대로 앞선 문서를 세션에 실제로 적재한 뒤 검사해 `integrity_problems`가 비었는지가 파일 이름(`valid-`/`invalid-`)과 맞는다(`forecast-report`는 범위 없이)
    - **적재 순서 판정 일치**: `fixtures-integrity/sequences/*.json`의 단계를 실제 API(`/facts`, 발행 단계는 T-602 전까지 `store`의 발행 함수)로 차례로 실행해, 위반이 생기는지가 파일 이름과 맞고 각 단계의 응답 revision이 `revisionAfter`와 같다
    - 새 사실 두 번 → revision 1·2, 같은 내용 재적재 → 그대로, `fixtures-integrity/`의 `invalid-*`는 422로 거부되고 revision이 그대로다, 422 응답이 계약 `gate-report` 스키마를 통과한다
  - `node scripts/dev.mjs --check`에 `✓ knowledge`
