- 인터페이스:
  - **분류(`classify.ts`)**: 세션에 발행된 예보가 있을 때(`session.completed`)의 메시지만 분류한다(되묻기 답·첫 메시지는 지금처럼 새 예보). 의도 enum = `why`·`save`·`draft`·`whatif`·`new_event`·`out_of_scope`. **키워드 규칙이 먼저**(예: 왜·이유·근거 → why / 저장·보관 → save / 초안·계획서·계획 → draft / 비 오면·요일·바꾸면 → whatif) — 규칙이 한 의도만 가리키면 LLM을 부르지 않는다(결정성·지연). 규칙이 없거나 둘 이상이면 Ollama 스키마 강제 enum 1회(예산 3초) → 실패·시간 초과는 `out_of_scope`. 분류 결과는 lead의 agent_step `note`에 남긴다(원문 없이 의도와 "규칙"/"LLM").
  - **why**: 발행된 예보 묶음(세션에 보관 — `sessions.ts`에 발행 묶음 필드 추가)으로 **템플릿 설명 문장**만 만든다(LLM 없음 — 요인 문장은 라벨 그대로라 풀어 쓰지 않는다). 문장: 요인 라벨(있으면, 상위 3), "비슷한 과거 행사의 실측을 근거로 삼았어요"(case 근거가 있으면 그 id), "개최 지역의 평시 방문 자료를 함께 봤어요"(평시 data 근거), "예측 모델이 추정한 범위를 따랐어요"(model 근거), OOD면 참고용 고지·미검증이면 모델 고지(T-304와 같은 문장·근거). **숫자 0개**, claimType 요인/설명, 같은 검증팀 → 게이트 B → 발행(knowledge `/publish`) → `claim`·`evidence`·`suggest`·`done{forecastId=기존 예보 id}`. 게이트 B가 (재작성 없이 템플릿뿐이므로) 막으면 발행 없이 `error(SERVICE_UNAVAILABLE, "설명 문장을 검증하지 못했어요")` → `done{forecastId=기존 예보 id}`(followup에서는 `done.forecastId`가 항상 기존 id — sse-sequence R7이 판정).
  - **save**: 발행된 예보의 records 스냅샷이 있으면(`getSnapshot`) 그대로, 없으면(T-304에서 저장 실패) `saveEvent`+`saveSnapshot` 재시도(예산 5초). 결과는 lead `agent_status`/`agent_step` note("예보서를 저장했어요" / "저장하지 못했어요 — 잠시 뒤 다시 눌러 주세요"). 발행 전이면 `error(OUT_OF_SCOPE, "먼저 예보를 받아야 저장할 수 있어요")`.
  - **draft**: 계획서 에이전트(T-306)가 들어올 자리 — `followups.ts`의 `planDraft` 한 곳으로 보내고, 이번 task에서는 `error(OUT_OF_SCOPE, "계획 초안은 계획서 담당이 곧 맡아요")`(T-306이 이 함수만 바꾼다).
  - **whatif**(P1, T-309): `error(OUT_OF_SCOPE, "비·요일을 바꿔 보는 기능은 준비 중이에요")`.
  - **new_event**: 지금처럼 "새 예보는 새 상담에서 시작해 주세요". **out_of_scope**: 할 수 있는 일(왜·저장·초안)을 안내하는 템플릿.
  - **`done.forecastId`**: 지금 `run-request.ts`는 이번 요청에서 forecastId가 바뀌었을 때만 id를 싣는다 → 후속 요청은 항상 기존 예보 id를 싣게 고친다(새 예보 경로는 그대로).
  - **요청 시각 고정(T-304 리뷰 Med)**: 요청 시작 때 KST 오늘을 한 번 정해 동네지기·예보관의 기준일 계산에 넘긴다(자정을 넘는 상담에서 두 팀원이 다른 기준일을 쓰지 않게).
