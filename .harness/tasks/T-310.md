# T-310: 게이트웨이 조회 프록시 — 행사·경계·예보서·근거·검증·인사이트·운영·날씨 + records 중계
- 레인/워커: L3 / gpt-6-astra        - 선행: T-303 완료(게이트웨이 런타임·클라이언트 — develop에 있음)
- 목표(한 문장): 웹이 `/api/*` 하나만 부르면 되도록 게이트웨이가 forecast·knowledge·records의 조회 API를 **계약 검증을 거쳐** 중계하고, 상류가 아직 없거나 계약을 어기면 숫자 대신 503을 준다.
- 읽을 것: packages/contracts/openapi/gateway.yaml(`/api/festivals`(필터 쿼리 — 새로 정함)·`/api/regions.topojson`·`/api/forecasts/{id}`·`/api/evidence/*`·`/api/weather`·`/api/validation/*`·`/api/insights/*`·`/api/ops/*`·`/api/records/{path}`(새로 정함)), packages/contracts/openapi/{forecast,knowledge,records}.yaml, docs/plan/05 §4(게이트웨이 경로 목록), services/gateway/src/clients/(T-301·T-303 — 발신 본문 검증 방식 그대로), `.harness/backlog.md` "계약 결정 대기"(evidence `?sessionId=`) 절, AGENTS.md §3·§5
- 허용 경로: `services/gateway/src/routes/`(라우트 묶음 하나 = 파일 하나: `festivals.ts`·`regions.ts`·`forecasts.ts`·`evidence.ts`·`weather.ts`·`validation.ts`·`insights.ts`·`ops.ts`·`records-relay.ts`), `services/gateway/src/clients/`(조회 함수 추가만), `services/gateway/src/app.ts`(등록 줄만), `services/gateway/tests/`, `services/gateway/fixtures/services/`(가짜 상류 응답 — 계약 픽스처에서 복사)
- 인터페이스(모든 응답은 **gateway.yaml 응답 계약으로 검증 뒤** 전달 — 상류 응답이 계약을 어기면 503 + 로그, 그대로 넘기지 않는다):
  - `GET /api/festivals?from&to&sido&type&level` → forecast `GET /v1/festivals/upcoming?from&to` + 게이트웨이에서 `sido`·`type`·`level` 필터(정렬은 상류 그대로)
  - `GET /api/regions.topojson` → forecast `GET /v1/regions/topojson`(`Cache-Control`·출처 헤더 유지)
  - `GET /api/forecasts/{id}` → records `GET /v1/snapshots/{forecastId}`(**T-505에서 추가 예정** — 지금은 404/503이면 503)
  - `GET /api/evidence/{id}` → knowledge `GET /v1/evidence/{id}`, `GET /api/evidence/stats` → knowledge `GET /v1/stats/datalab-usage`
  - `GET /api/weather?lat&lng&at` → forecast `GET /v1/weather`(T-210 전이면 503)
  - `GET /api/validation/backtest` → forecast `/v1/backtest/latest`, `/api/validation/preregistration` → `/v1/preregistration/scores`, `/api/validation/model-card` → `/v1/model-card/latest`
  - `GET /api/insights/{key}` → forecast `/v1/insights/{key}`, `GET /api/insights/datalab-spec` → forecast `/v1/datalab/spec`(근거 수는 knowledge `datalab-usage`로 채운다 — 합치는 규칙은 계약 스키마 설명대로, 없는 값은 null)
  - `GET /api/ops/runs` → forecast `/v1/runs`, `GET /api/ops/status` → forecast `/v1/ops/freshness` + 모델 카드 + knowledge `/v1/stats/graph` + `reports/evals/latest.json`(있으면)을 계약 `ops-status`로 조립(없는 부분은 계약이 허용하는 null)
  - `/api/records/{path}` GET·POST·PUT → records 같은 경로, **허용 목록**(gateway.yaml 설명의 목록)만, 요청 본문·응답은 records.yaml의 해당 경로 계약으로 검증, docx는 바이너리 그대로(Content-Type·Content-Disposition 유지). 목록 밖 404
  - 공통: 상류 시간 제한 5초, 실패는 503(`{code, message}` — 계약 오류 모양), 상류 주소는 기존 설정(`FORECAST_URL` 등)

  - `npm -w services/gateway run build`·`lint`, `node scripts/dev.mjs --check --only gateway`에 `✓ gateway`
