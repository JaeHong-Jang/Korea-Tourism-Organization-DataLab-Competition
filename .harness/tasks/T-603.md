- 읽을 것: docs/plan/09 §7(발행 상태 — 조회는 published만)·§8(질의 표)·§9(화면 표현)·§10(API), packages/contracts/openapi/knowledge.yaml(`/v1/sessions/{id}/graph`·`/v1/claims/{id}/evidence`·`/v1/evidence/{id}`·`/v1/ontology`), packages/contracts/schemas/evidence.schema.json, services/knowledge(T-601·T-602 결과 — 응답은 `api/contract_response.py`를 거친다), AGENTS.md §3·§5
- 허용 경로: `services/knowledge/ontology/queries/`(질의 하나 = 파일 하나: `claim_evidence.rq`·`forecast_lineage.rq`·`datalab_usage.rq`·`rule_trace.rq`·`session_summary.rq`), `services/knowledge/src/knowledge/{query,api}/`(질의 실행기·라우트 — 라우트 하나 = 파일 하나), `services/knowledge/tests/`(질의 결과 스냅샷 픽스처 `tests/fixtures/queries/`)
- 인터페이스:
  - `query.run(name, bindings, scope)`: `.rq` 파일을 읽어 pyoxigraph로 실행. 범위는 한 세션 named graph + 기준 그래프(다른 세션 안 봄). 결과는 파이썬 dict 목록(키 = SELECT 변수)
  - **발행분만**: 문장·근거를 돌려주는 모든 경로는 `cc:status "published"`인 문장과 그 문장이 인용한 근거만(draft·candidate·rejected는 404 또는 빈 목록). 세션 그래프 GET도 발행분만 JSON-LD로(계약 `jsonld/context.jsonld`로 compact)
  - `GET /v1/claims/{id}/evidence` → 계약 `evidence` 배열(근거 카드 데이터 — 출처·기간·공개일·규칙·가정 포함). `GET /v1/evidence/{id}` → 계약 `evidence` 하나(발행 문장이 인용하지 않은 근거는 404). `GET /v1/ontology` → TTL(`text/turtle`)
  - RDF → 계약 JSON 복원은 적재할 때의 원문과 **같은 내용**이어야 한다(적재한 evidence 픽스처를 다시 읽으면 canonical 비교로 같음)
  - 질의 5종이 답하는 것: 09 §8 표 그대로(문장의 근거와 출처 / 예보의 관측값·모델 버전·가정 계보 / 데이터랩 메뉴별 근거 사용 횟수와 데이터랩까지 이어지는 발행 문장 비율 / 판정에 쓰인 규칙·조항 / 세션의 에이전트 작업·검사 결과)
- 수용 기준(실행 명령):
  - `uv run --package crowdcast-knowledge pytest -q services/knowledge/tests` 통과:
    - 계약 픽스처(행사·유사·평시·예보·문장 draft→candidate→발행 — `fixtures-integrity/sequences/valid-new-forecast.json` 순서)를 적재·발행한 세션에서 질의 5종 결과가 스냅샷 픽스처와 같다
    - 발행 전(candidate)에는 `/claims/{id}/evidence`·`/evidence/{id}`가 404, 발행 뒤 200이고 응답이 계약 스키마 통과
    - 다른 세션의 문장·근거는 보이지 않는다
    - 근거 복원: 적재한 evidence 원문과 조회 결과가 같다
  - `node scripts/dev.mjs --check --only knowledge`에 `✓ knowledge`
  - 질의 시간: 세션 1개(약 300트리플) 기준 질의별 중앙값을 리포트에 적는다
