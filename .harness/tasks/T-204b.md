- 인터페이스:
  1. **사람 수 정수**: 응답의 `unit ∈ {명, 명/일}` Quantity(`peakConcurrent`·`dailyMean`)의 p10·p50·p90·value를 **반올림(0.5는 올림) 정수**로 낸다 — API 조립에서만. 판정 확률·등급은 반올림 전 표본 그대로(바뀌면 버그 — 테스트). 모델 내부·백테스트 지표는 손대지 않는다.
  2. **구간 꼬리는 한 곳에만**: 구간 모드에서 `judgment.reasons[].text`는 규칙 문구(`interval_text`가 있으면 그것, 없으면 `text`)만 쓰고 `interval_display`를 붙이지 않는다. `interval_display`는 `probabilities[].display`에만 남고, 그 숫자는 1번의 **같은 반올림 정수**(`{p10:,}~{p90:,}명`)다. 근거 조각(RuleEvidence) 문구도 사유 문구와 같게.
  3. **자체 판정 문장 구분**: `rule-internal-50pct.interval_text` = "자체 기준 — 순간 최대 예측 중앙값이 법정 인원 기준 이상이라 수립 대상으로 봅니다. 참고용 — 담당자 검토 필수"(확률·% 없음). 확률 모드 `text`는 그대로.
  4. **요금 "미상"**: `detect_ood`에서 학습 범위가 "미상" 범주 하나뿐인 범주형 피처(지금은 `fee`)는 전부 결측과 같게 범위 검사에서 뺀다 — 모델 파일(`models/<ver>/ood.json`)은 불변이므로 **검사 시점 규칙**으로(재학습 없음). 범주 목록은 `event_features.py`에서 읽는다. `hazard_*`는 그대로 검사.
  5. **runId에 설정 포함(T-205 리뷰 Med)**: `run_identifier`의 입력 해시에 예보 수치·문구를 바꾸는 설정(`configs/{thresholds,peak_profiles,checklist}.yaml` — 실제로 읽는 파일 전부)의 SHA-256을 넣는다 → 이 task의 문구 변경 뒤 재실행하면 runId가 바뀐다. 테스트: 설정 한 줄 변경 → 다른 runId.
