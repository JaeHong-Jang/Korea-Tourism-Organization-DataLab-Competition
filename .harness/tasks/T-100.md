- 인터페이스:
  - `uv run --package crowdcast-forecast python -m crowdcast.data.mcst_festivals` → parquet + QC 리포트. 열: `year, sido, sigungu_name, festival_name, type_raw, type(eventType enum 매핑, 모르면 "기타"), start_date, end_date, days, venue, host, budget_krw(원 정수, 없으면 null), visitors_announced(정수, 없으면 null), visitors_announced_meaning(열 이름 원문: 예 "전년도 방문객"), source_file, source_sheet, source_row`

## 게이트 피드백 1회차 (게이트 3 교차 리뷰 FAIL — gpt-6-sol, 원본 xlsx 대조) — 워크트리에 1차 결과가 있다. 아래를 고치고 수용 기준을 모두 다시 실행하라
1. [High] `mcst_festivals.py:63` 날짜 정규식이 문자열 일부만 받아들인다 — `2023 세부현황` 757행 `05.04-05.06`이 2005-04-05 하루로, 733행 `2023.12..30~2024.01.28.`이 끝 날짜 하루로 저장됐다. → 기간 전체가 형식에 맞을 때만 채택(전체 일치), 앞 날짜가 깨졌으면 뒤 날짜만 쓰지 않는다. 연도 없는 `MM.DD`는 그 파일의 연도로 해석한다. 위 두 행을 테스트 케이스로 넣는다.
2. [High] `mcst_festivals.py:146` 2021년 원본 `J5`의 `백만원` 단위가 머리글 아래 행에 있어 감지하지 못해 원본 예산이 숫자인 871행이 null이다(예: `서울!I6=225`). → 병합 머리글과 그 아래 단위 행을 함께 읽어 원 단위로 환산. QC 리포트에 연도별 예산 채움률을 넣는다.
3. [Med] `mcst_festivals.py:168` 2017년 `대전!E5=4.7~4.9`와 `F5=3일간`처럼 일수가 별도 셀인 확정 일정 6건이 null — 기간과 명시 일수를 따로 파싱한 뒤 일치 여부를 검사한다.
4. [Med] `mcst_festivals.py:160` `2018 10_강원도` 82행(시트 전체에 병합된 "전년대비 축제 증가사유" 주석)이 행사 1건으로 들어갔다 — 행사명이 다른 열에서 복원된 병합 값이면 제외하고, 시도 값이 시트의 시도와 맞는지 검증한다.
5. [오케스트레이터 추가] 날짜를 null로 둔 행도 원문을 잃지 않게 열 두 개를 더한다: `date_text`(날짜 칸 원문 그대로), `planned_month`(원문에서 확실히 읽히는 개최 달 1~12, 예 `10월중`·`2024. 7.`→ 해당 달, `9월 말~10월 초`처럼 두 달이면 null). QC 리포트에 연도별 `planned_month` 채움률을 넣는다. 다음 task(행사 마스터)가 실제 개최일을 맞출 때 쓴다.

## 게이트 피드백 2회차 (오케스트레이터 게이트 2·4 — 마지막 재디스패치)
1회차 지적 5건은 원본 행 대조로 모두 확인했다(757·733행, 대전 E5, 강원 82행, 2021 서울 I6, date_text·planned_month). 남은 것은 **회귀 하나**다.
1. [Med·회귀] 전체 일치로 바꾸면서 날짜 채움률이 떨어졌다(2024년 0.45 → 0.41). 2023~2025년에 `월.일`이 두 번 이상 보이는데 날짜가 빈 행이 96건이고, 대부분 **끝에 붙은 상태 표기** 때문이다: `9. 28.~9. 29.(예정)`, `05.03.~05.12.(예정)`, `4.20.~4.22.예정`, `3.22~3.24\n(예정)`, `6. 14. ~ 6. 16.(예정)`, `09.01.~09.03\n(유동적)`, `2023.2.3.~2.4.(예정)`, `09.21..~09.23.`(점 두 개).
   → 날짜 파싱 **전에** 끝의 상태 표기(`(예정)`·`예정`·`(잠정)`·`(유동적)`, 앞뒤 줄바꿈·공백)만 떼고, 떼어 낸 뒤의 문자열이 기간 형식과 **전체 일치**할 때 채택한다. 연속된 점(`..`)은 하나로 본다. 원문은 `date_text`에 그대로 둔다.
   → 계속 null로 두는 것(바꾸지 말 것): 두 기간(`4.30.~6.4. / 9.16~10.22.`), 기간 중 며칠(`9.2~9.7중 3일간`, `(중 2일)`), 월만(`24.10.~25.1.`), 앞이 깨진 것(`02.21.~.4.30.`), 연도를 넘는 것(`12.31.~'23.1.1.`).
   → 위 예시를 모두 회귀 테스트로 넣고, QC 리포트의 연도별 날짜 채움률이 1회차 결과(2023 0.45·2024 0.45·2025 0.59 이상)보다 낮아지지 않는지 리포트에 표로 적는다.
