- 인터페이스:
  - 해시 규칙(**정본 — 문서와 코드가 같아야 한다**): `payload` = `{seq, forecastId, eventId, registeredAt, leadDays, forecast}`를 **키 정렬·공백 없는 UTF-8 JSON**(정수는 정수로, `JSON_UNESCAPED_UNICODE|JSON_UNESCAPED_SLASHES`)으로 직렬화 → `payloadHash = sha256(payload)` 16진 소문자. `hash = sha256(prevHash + payloadHash)`(16진 문자열 이어 붙임). 첫 항목의 `prevHash` = `0`×64. 규칙을 `services/records/src/Ledger/README.md`에 적는다.
  - `POST /v1/ledger` body `{forecastId, eventId, leadDays, forecast:{dailyMeanP10,dailyMeanP50,dailyMeanP90,level}}` → 서버가 `seq`(1부터 연속)·`registeredAt`(서버 KST 시각)·해시를 붙여 저장, 계약 `ledger-entry`로 응답. 같은 `forecastId`는 한 번만(409). 요청·응답 계약 검증. `eventId`는 records의 행사여야 한다(삭제 표시 포함 — 이력).
  - `GET /v1/ledger` → 전체(seq 순), `GET /v1/ledger/verify` → `{valid, count, brokenAt}`(처음 어긋난 seq, 없으면 null) — 저장된 행으로 해시를 **처음부터 다시 계산**해 비교.
  - append-only: `004_ledger_guard.sql`로 `ledger_entries`의 UPDATE·DELETE·같은 seq/forecastId 재삽입을 트리거로 막는다(T-501의 스냅샷 방식 — `recursive_triggers` ON 전제, REPLACE·rowid 우회 포함).
  - 동시 등록: seq·prevHash를 한 트랜잭션(`BEGIN IMMEDIATE`)에서 읽고 쓴다.
  - 내보내기: `php services/records/bin/ledger-export.php` → `reports/preregistered/ledger.csv`(열: seq, forecastId, eventId, registeredAt, leadDays, dailyMeanP10, dailyMeanP50, dailyMeanP90, level, payloadHash, prevHash, hash). 같은 원장이면 같은 바이트(재현 가능).
