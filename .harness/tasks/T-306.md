- 인터페이스:
  - **섹션 문장(`plan-templates.ts`, LLM 없음 — P0)**: 발행 묶음(`session.published`)의 예보·근거·발행 문장에서만. 숫자는 자리표시자(T-304 수치 문장과 같은 규칙), 판정·권고는 규칙 정본 문구 그대로.
    - `overview`: 행사 개요(행사명·일시·장소 — 행사 사실 문장, 근거 = 행사·예보) + 판정 문장(발행된 판정 claim 재사용 가능 — 새 id로 복사하지 말고 **이미 발행된 문장 id를 그대로 인용**할 수 있으면 그렇게).
    - `crowd-timeline`: 순간 최대 구간 문장(자리표시자), `peakHours`·`hourlyProfile`이 비어 있으면 "시간대별 분포 자료가 없어 담당자가 채워야 해요" → 이 섹션은 문장이 있어도 `검토 필요`.
    - `non-crowd-risks`: 체크리스트(권고) 문장들 + 위험 요소(hazards)가 있으면 그 판정 사유.
    - `routes-evacuation`·`traffic-parking`·`medical-toilets`: 체크리스트 항목 중 해당 주제(키워드 규칙 — 대피·동선 / 교통·주차 / 의료·화장실)가 있으면 그 권고 문장, 없으면 `검토 필요`(빈 body, 이유는 섹션 제목 옆 안내로 T-504가 표시).
    - `staffing`·`organization`·`weather-emergency`: 이번에는 **`검토 필요`**(인력 산정은 행안부 매뉴얼 H5 확인 뒤 T-306b, 날씨는 T-210 뒤) — 지어내지 않는다.
  - **검증·발행**: 새로 만든 섹션 문장만 draft → 같은 검증팀(출처확인·숫자대조·법규담당·깐깐이) → 게이트 B → 발행(followup 순서 규칙 — T-305 why와 같은 경로·후보 정리 규칙 재사용). 게이트 B가 막으면 그 섹션은 `검토 필요`로 내려 보내고 나머지로 계속(섹션 하나 때문에 초안 전체를 버리지 않는다) — 단 발행 전 문장은 SSE로 보내지 않는다.
  - **저장**: records `POST /v1/plans`(계약 `plan` — 9섹션 enum 순서, `작성됨` 섹션 body = claimIds 순서의 rendered를 `\n`으로 이은 것, `lockedFields`는 숫자 자리표시자가 있는 필드). 422면 이유를 로그에 남기고 `error(SERVICE_UNAVAILABLE, "계획 초안을 저장하지 못했어요")`. 같은 예보로 두 번째 요청이면 기존 계획을 돌려준다(409 → 조회).
  - **응답**: 발행된 섹션 문장 `claim`·`evidence` → `suggest`에 `{id: "plan-docx", label: "계획 초안 docx 받기", href: "/api/plans/{id}/export.docx"}`(이 task의 `routes/plans.ts`가 이 경로를 records로 프록시 — 웹 버튼 연결은 T-406) → `done{forecastId=기존 예보}`.
