- 레인/워커: L2 / gpt-6-astra        - 선행: R-01 통과
- 목표(한 문장): `scripts/dev.mjs`가 띄우는 예측 서비스 골격을 만들고, 모든 응답을 계약 스키마로 검증할 수 있는 도구와 테스트 틀을 둔다.
- 읽을 것: docs/plan/05 §2·§8·§12, packages/contracts/openapi/forecast.yaml, packages/contracts/check/python_check.py(스키마 등록 방식 참고), AGENTS.md §3·§5
- 허용 경로: `services/forecast/src/crowdcast/api/` (`__init__.py`, `app.py`, `routes/__init__.py`, `routes/health.py`, `contract.py`), `services/forecast/src/crowdcast/config.py`, `services/forecast/tests/api/`
- 인터페이스:
  - `uv run --package crowdcast-forecast uvicorn crowdcast.api.app:app --port 8010` 로 뜬다(dev.mjs 등록 명령 그대로)
  - `GET /health` → `{"status":"ok","version":"0.1.0"}` (openapi/forecast.yaml)
  - `crowdcast.config`: 레포 루트·`data/`·`models/`·`reports/` 경로, `.env`(python-dotenv) 읽기. 키는 로그에 남기지 않는다
  - `crowdcast.api.contract.validate(schema_name, obj)` → 계약 스키마(`packages/contracts/schemas`, `$id` 등록, 형식 검사 포함)로 검증하고 실패 시 예외. 라우트 응답 검증에 쓴다
  - 라우트는 리소스 하나당 파일 하나(`routes/<리소스>.py`), `app.py`는 등록만
- 수용 기준(실행 명령):
  - `uv run --package crowdcast-forecast pytest -q services/forecast/tests/api` 통과: health 응답이 스키마에 맞음, `contract.validate`가 `packages/contracts/fixtures/forecast/`의 valid는 통과·invalid는 거부
  - `node scripts/dev.mjs --check` 출력에 `✓ forecast` (다른 서비스는 "아직 없음"이어도 됨)
