- 레인/워커: L2 / gpt-6-astra        - 선행: T-203(모델·백테스트 v1)·R-04(데이터·누수 검토) 통과
- 목표(한 문장): 게이트웨이 예보팀이 부르는 예측 API를 계약 그대로 열고, 모든 숫자에 근거 조각(데이터·사례·모델·가정·규칙)과 피처별 관측·예측 실행 계보를 붙여 근거 그래프가 S03·S08·S09로 검사할 수 있게 한다.
- 읽을 것: docs/plan/06 §3(공개 시점)·§5(분포·OOD)·§9(D-14 규칙)·§12(근거 조각 표 — **정본**), docs/plan/09(근거 그래프 적재·계보), packages/contracts/openapi/forecast.yaml, packages/contracts/schemas/{forecast,evidence,region-baseline,similar-event,factor,judgment,model-card,backtest-summary,common}.schema.json, packages/contracts/fixtures/{forecast,evidence,region-baseline,similar-event}/, packages/contracts/jsonld/master-ids.json(데이터셋·가정·규칙 id), services/forecast/src/crowdcast/{rules,models,features,data/geocode.py}(T-102·T-202·T-203 — **호출만**), `.harness/backlog.md` "T-204" 절, AGENTS.md §3·§5
- 허용 경로: `services/forecast/src/crowdcast/api/routes/`(라우트 하나 = 파일 하나: `geocode.py`·`predict.py`·`whatif.py`·`similar.py`·`baseline.py`·`model_card.py`·`backtest.py`), `services/forecast/src/crowdcast/api/app.py`(라우트 등록 줄만), `services/forecast/src/crowdcast/api/assemble/`(예보 조립: 관측·예측 실행·근거·요인 연결·카드 — 파일 여럿), `services/forecast/src/crowdcast/analytics/`(`similar.py`·`baseline.py`), `services/forecast/tests/api/`
- 인터페이스(요청·응답 모두 계약 검증 — T-201 도구, 실패는 400/500으로 드러낸다):
  - `POST /v1/predict` body `event` → `forecast`:
    - **기준 시점** `asOf = min(오늘 KST, 시작일 − 14)`(06 §9 — 언제 불러도 D-14 정보만). 피처는 T-203 `features/build.py` 그대로, `availability` 위반이면 500(숨기지 않는다)
    - `id` = `f-` + (eventId·asOf·modelVersion)의 해시(계약 패턴) — 같은 입력 = 같은 id·같은 숫자(시드 고정)
    - 분포·순간 최대·판정·체크리스트 = T-203 `models/distribution.py` → T-202 `rules/{peak,judge,checklist}.py`
    - `observations`: **자료에서 온 피처마다 1개**(행사 입력 자체 — 유형·기간 — 는 관측이 아님). `datasetId`는 master-ids의 데이터셋, `availableAt ≤ asOf` 정확히 1개, `sigunguCode`. `predictionRun`: `modelRunId`(모델 카드 id)·modelVersion·asOf·observationIds·trainRange
    - `evidence`: 06 §12 표 그대로 — ModelEvidence(분포·요인·모델 버전·학습 범위), DataEvidence(개최지 평시 — `/baseline`과 같은 id), CaseEvidence(전회차·유사 — `/similar`과 같은 id), AssumptionEvidence·RuleEvidence(T-202 `rules/evidence.py`가 만든 것 그대로). id는 내용 해시(같은 입력 = 같은 id)
    - `factors`: T-203 SHAP 상위 5개 → **각 요인의 `evidenceIds`는 비어 있으면 안 된다**(그 피처의 관측이 들어간 DataEvidence/CaseEvidence, 없으면 ModelEvidence)
    - `ood`·`oodReasons`: T-203 `ood.py` + **연속성 끊김 지역**(인천 28110·28140·28260, 06 §1): 2026-07-01 이후 관측을 쓰지 않고 2026-06-30까지만 쓰며 `oodReasons`에 "행정구역 개편 — 2026-06-30까지 자료만" 한 줄
    - `peakHours`·`hourlyProfile`·`composition`: T-202 설정(운영 시간·체류)과 개최지 구성비(`region_daily` 외지인·외국인 비중, asOf 이전)에서 결정적으로. 모르는 값은 계약이 허용하는 방식(null·빈 배열)으로 — **지어내지 않는다**
  - `POST /v1/whatif` `{event, changes}` → `changes`는 `startsAt`·`endsAt`·`timeOfDay`·`fee`·`type`·`hazards`만 허용(그 밖의 키는 400), 적용 후 `/predict`와 같은 경로
  - `POST /v1/similar` `event` → `similar-event[]`(최대 5): 라벨(`is_primary`, `available_at ≤ asOf`, 골든 제외)에서 유형·규모대·지역으로 가까운 순. `measured`·`announced`에 **단위 메타데이터**(06 §2), `unitsComparable`은 단위가 같을 때만 true
  - `GET /v1/baseline?sigunguCode&before` → `region-baseline`: `before` 이전 4주 같은 요일 평균·외지인 비중, `available_at ≤ before`인 날만, 연속성 끊김 규칙 동일
  - `POST /v1/geocode` → T-102 `geocode.candidates` 그대로(모호하면 여러 개)
  - `GET /v1/model-card/{version}`·`GET /v1/backtest/{runId}` → 버전별 `models/<version>/model_card.json`·`reports/backtest/<runId>/backtest.json`을 계약 검증 뒤 그대로, `latest`는 **사용 모델 포인터** `reports/backtest/promoted.json`의 `runId`·`modelVersion`이 가리키는 것(게이트웨이가 `latest`로 부른다 — `latest.json`은 게이트 전 후보라 쓰지 않는다, 공유 `models/model_card.json`은 없다). 없으면 404
  - **모델 읽기 규칙(T-203 발행 방식 — backlog "T-204" 절)**: `/predict`는 **사용 모델 포인터** `reports/backtest/promoted.json`의 `modelVersion` 폴더(`models/<ver>/`)만 쓴다(`verdict`가 `미검증`이면 **예보 응답에 이 상태를 실어** — 계약에 자리가 없으면 `CONTRACT-CHANGE` 제안 — 웹이 인원·판정 옆과 인쇄·docx에 "골든 사례 0건 — 사례 재현 검증 전 임시 사용"을 표시할 수 있게 한다, 06 §8), 포인터가 없으면 503 — 실행 폴더는 완성된 뒤 한 번에 드러나고 바뀌지 않는다. `.staging-*`·`g0/`는 읽지 않는다, 서비스 기동 때 한 번 읽고 파일이 바뀌면 다음 요청에서 다시 읽는다(버전이 바뀌면 `predictionRun.modelVersion`도 바뀐다). 달력 피처는 T-203 규칙 달력 그대로(임시공휴일 미반영) — 이를 가정 근거로 보이려면 master-ids에 새 가정 id가 필요하므로 **지어내지 말고** 리포트에 `CONTRACT-CHANGE` 제안으로 적는다
