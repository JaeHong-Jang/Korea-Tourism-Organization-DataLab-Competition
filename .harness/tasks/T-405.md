- 인터페이스:
  - **스트림**(`lib/team-stream/`): `POST /api/team/sessions` → sessionId, `POST /api/team/sessions/{id}/messages` 응답을 `fetch` + `ReadableStream`으로 읽는다(EventSource는 POST 불가). 이벤트마다 계약 `sse-event` 스키마 검증, 받은 순서를 `sequenceProblems(events, {mode:"new"})`로 검사 — 위반이면 화면에 오류 카드(숨기지 않는다). 연결 끊김·중단 버튼(AbortController)
  - **대화(M2-F1)**: 첫 화면 = 큰 입력창 + 예시 칩 3개("10월 18일 영종 씨사이드파크에서 불꽃축제를 해요" 외 유형이 다른 2개 — 실제 기관 사칭 없는 평범한 문장) + 팀장 펫 인사. 채운 주요 버튼은 **"보내기" 하나**(나머지는 보조 버튼 — 11 원칙 2). `ask` 이벤트 → 질문 말풍선 + 선택지 버튼(`options`), 시각 질문(`field:"time"`)은 날짜 고정 + 시작·종료 시각 입력 두 칸, `hazards`는 여러 개 고르기 + "해당 없어요", 주최 유형은 버튼 4개. 답은 `{text, answer}`로 같은 세션에 보낸다(직접 입력도 가능)
  - **행사 카드(M2-F2)**: `event_card`로 필드 칩(채운 값 = 실선, 빠진 값 = 점선). 칩을 누르면 그 필드를 고치는 입력 → 새 메시지로 다시 보냄
  - **작업판(M2-F3)**: 팀장 + 분석·검증·보고 3팀 × 4 펫(T-430 `PetAvatar` 13명, 이름표), 상태 5종은 **`agent_status`만으로** 그린다(추측 애니메이션 금지). `gate` → 게이트 도장(통과) / 위반이면 해당 팀 펫이 손들기 + 위반 요약(누르면 펼침). 펫을 누르면 `GET /api/team/sessions/{id}/steps`의 그 팀원 기록(입력 요약·출력 근거 id·ms·LLM 사용 여부·모델) 서랍
  - **예보서 미리보기(M2-F4)**: `forecast`(게이트 A 뒤) → `KeyNumber`·`LevelBadge`·`RangeBar`(T-402). **발행 전 문장은 보이지 않는다**(claim 이벤트가 오면 그때만 — T-304). 버튼 [전체 예보서]·[계획 초안 받기]·[저장]은 `done.forecastId`가 있을 때만 활성, 없으면 비활성 + 이유 한 줄("검증팀 발행 뒤에 열려요"). `error` → 펫 얼굴 오류 상태(T-402 `ErrorState`) + 다시 시도
  - 접근성: 스트림 진행은 `aria-live="polite"` 요약 한 줄(이벤트마다 읽지 않음), 키보드로 칩·질문 버튼·펫 서랍 조작, reduced-motion이면 펫 동작 정지
