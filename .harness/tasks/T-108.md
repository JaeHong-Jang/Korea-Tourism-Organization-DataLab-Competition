- 인터페이스:
  - **자산 7개**: 단계마다 하나(키 `crowdcast/<stage>`), 의존 = 파이프라인 순서, 실행 본문 = 기존 `execute_stage`(또는 같은 진입점) 호출 — **로직 복제 금지**. 메타데이터: 산출물 경로·sha256(`output_files`)·행 수·걸린 시간·runId.
  - **asset check**: 단계마다 기존 게이트 함수 결과를 check로(실패 = check 실패, 게이트 메시지 그대로). 실패하면 뒤 자산을 막는다(CLI와 같은 규칙).
  - **스케줄**: 매일 06:00 KST 전체 실행 — **기본 상태 STOPPED**(자동 실행 안 함, 공유 호출 한도 보호).
  - **실행 기록 연동**: Dagster 실행도 `reports/runs/<runId>/run.json`을 같은 형식으로 남긴다(운영 화면 S8이 그대로 읽게) — 기존 `run_record` 사용.
  - **계보 내보내기**: `python -m crowdcast.pipeline.dagster_defs lineage --out reports/runs/lineage.json` → 자산 키·의존·입력/출력 파일·마지막 실행 runId·sha256(계약 없음 — 파일 형식을 `docs/reference/dagster.md`에 적는다, T-605가 읽는다).
  - 실행: `uv run --package crowdcast-forecast --group pipeline dagster dev -m crowdcast.pipeline.dagster_defs`(문서에).
- 수용 기준: `pytest -q services/forecast/tests`(Dagster 테스트는 가짜 단계 함수로 in-process materialize — 의존 순서·check 실패 시 하류 중단·run.json 기록·계보 JSON), ruff, `dagster definitions validate -m crowdcast.pipeline.dagster_defs` 통과. 실제 `dagster dev` 화면 스크린샷(`reports/figures/screens/T-108-lineage.png`)은 오케스트레이터.
