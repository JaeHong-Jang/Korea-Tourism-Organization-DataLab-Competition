# T-505: 예보 id로 스냅샷 조회(P0) + 행사 후 실측 입력 + 공유 링크(P1)
- 레인/워커: L5 / gpt-6-sol        - 선행: T-502(스냅샷)·T-504(초안) 완료
- 목표(한 문장): 게이트웨이 `/api/forecasts/{id}`와 공유 링크가 발행 스냅샷 하나를 예보 id·토큰으로 바로 열 수 있게 하고, 행사가 끝난 뒤 담당자가 실측을 적어 채점·내 행사(S5)가 쓸 수 있게 한다.
- 읽을 것: packages/contracts/openapi/records.yaml(`/v1/snapshots/{forecastId}`(새로 정함)·`/v1/actuals`·`/v1/shares`·`/v1/shares/{token}`(새로 정함)), packages/contracts/schemas/{forecast-report,common}.schema.json(`quantity` — 단위·시간 단위·값 종류), services/records(T-501~T-504 — 계약 검증·불변 트리거·원장 방식 그대로), `.harness/backlog.md` "T-505" 절, AGENTS.md §3·§5
- 허용 경로: `services/records/src/Snapshots/`(예보 id 조회 컨트롤러·저장소 함수 추가), `services/records/src/Actuals/`(새), `services/records/src/Shares/`(새), `services/records/src/Routes/RecordsRoutes.php`(라우트 등록 줄만), `services/records/migrations/007_actuals_shares.sql`, `services/records/tests/`
- 인터페이스(요청·응답 계약 검증 — 기존 방식):
  - **`GET /v1/snapshots/{forecastId}`**(P0): 발행 스냅샷 하나(forecastId 전역 유일 — 인덱스), 없으면 404. 삭제 표시된 행사의 스냅샷도 이력으로 연다
  - `POST /v1/actuals` `{eventId, actual}`: `actual`은 계약 `quantity` — **단위·시간 단위·공간 범위·값 종류(실측)**가 반드시 있어야 하고(06 §2 단위 메타데이터), `eventId`는 records 행사. 저장은 추가만(같은 행사에 여러 번 적으면 이력으로 쌓이고 최신이 기본, UPDATE·DELETE 금지 — 트리거). 응답 = 저장된 실측(서버 시각 포함)
  - `POST /v1/shares` `{forecastId}` → `{token}`(`sh-` + 난수 24자 이상, 추측 불가), 같은 예보에 다시 만들면 같은 토큰. `GET /v1/shares/{token}` → 그 스냅샷(읽기 전용). 토큰은 로그에 남기지 않는다
- 수용 기준(실행 명령):
  - `cd services/records && composer test && composer stan` 통과: 스냅샷 id 조회(있음·없음·삭제 표시 행사), 실측 단위 누락·값 종류 예측·없는 행사 → 422, 이력 누적·최신, 실측 UPDATE·DELETE·REPLACE 거부(T-501 방식), 공유 토큰 형식·재사용·없는 토큰 404·토큰 추측 불가(난수 소스)
  - `node scripts/dev.mjs --check --only records`에 `✓ records`
  - 수동: 게이트웨이(develop, T-310) `/api/forecasts/{id}`·`/api/records/shares`로 한 번씩 curl — 리포트에 결과
- 범위 밖: 채점 계산(T-207·T-208), 내 행사 화면(T-409), 공유 화면(T-409)
