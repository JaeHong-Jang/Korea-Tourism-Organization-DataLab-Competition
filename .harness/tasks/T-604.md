# T-604: 근거 통계 + 그래프 크기 + 모델 카드 등록(기준 그래프 ModelRun)
- 레인/워커: L6 / gpt-6-astra        - 선행: T-603 완료(질의 5종·발행 그래프·근거 조회 — develop에 있음), T-203 완료(모델 카드 = `reports/backtest/promoted.json` → `models/<modelVersion>/model_card.json`)
- 목표(한 문장): 근거 대시보드·서식4가 쓸 **근거 통계**(발행 문장 중 근거 연결·데이터랩까지 이어지는 비율, 데이터셋별 인용 수, SHACL 통과율)와 **그래프 크기**를 계약 그대로 내고, 백테스트가 만든 **모델 카드를 기준 그래프의 ModelRun으로 등록**해 예보 계보 규칙(S08)이 실제 모델 실행을 가리키게 한다.
- 읽을 것: packages/contracts/openapi/knowledge.yaml(`/v1/stats/datalab-usage`·`/v1/master/model-runs`·`/v1/stats/graph`), packages/contracts/schemas/{datalab-usage,model-card,ops-status}.schema.json(`graphStats`), packages/contracts/fixtures/{datalab-usage,model-card,ops-status}/, docs/plan/09 §1(기준 그래프 = master TTL + 모델 카드 적재)·§3 S08·§5 API 표, services/knowledge/src/knowledge/store/master.py(`register_model_run` — 이미 있다, 다시 만들지 않는다), services/knowledge/ontology/queries/datalab_usage.rq(지금 모양은 계약과 다르다), services/knowledge/src/knowledge/api/{app,validate,master_version,contract_response}.py, AGENTS.md §3·§5
- 허용 경로: `services/knowledge/src/knowledge/api/`(새 파일 `stats.py`·`model_runs.py` + `app.py` 등록 줄·기동 적재, `validate.py`는 결과 기록 한 줄만), `services/knowledge/src/knowledge/query/`(통계 질의 실행), `services/knowledge/src/knowledge/store/`(검증 기록 — 새 파일 `validation_log.py`), `services/knowledge/ontology/queries/datalab_usage.rq`(계약 모양으로 고침 — 다른 질의는 건드리지 않는다), `services/knowledge/tests/`, `services/knowledge/tests/fixtures/`
- 인터페이스(모든 응답은 계약 스키마로 검증 뒤 전달 — `contract_response` 방식 그대로):
  - `POST /v1/master/model-runs`(본문 = `model-card`): `register_model_run` 호출 → 200 `{masterVersion}`. 같은 id·같은 내용 재등록 = 버전 그대로 200, 같은 id·다른 내용 409, 스키마 위반 422(`{code, message}` 또는 기존 오류 모양 — 앱의 기존 규칙을 따른다)
  - **기동 적재**: 서비스가 뜰 때 **사용 모델 포인터** `paths.DATA_ROOT / "reports/backtest/promoted.json"`의 `modelVersion`으로 `models/<modelVersion>/model_card.json`을 찾아 같은 함수로 등록(공유 `models/model_card.json`은 없다 — T-203 발행 규칙)(재기동해도 같은 내용이면 버전이 오르지 않는다), 등록 결과(모델 버전·masterVersion)를 로그 한 줄. 파일이 없거나 계약 위반이면 **기동은 계속**하고 경고 로그(예보 계보 검사 S08이 실패하게 두는 것이 정직하다 — 가짜 ModelRun을 만들지 않는다)
  - `GET /v1/stats/datalab-usage` → 계약 `datalab-usage`: `publishedClaims`(발행 문장 수), `claimsWithEvidence`(근거 1개 이상 인용한 발행 문장 수), `claimsReachingDatalab`(인용 근거가 `derivedFromDataset` 또는 예보 계보 `aboutForecast/wasGeneratedBy/used/derivedFromDataset`로 **`datalabMenu`가 있는 기준 데이터셋**까지 이어지는 발행 문장 수), `evidenceByDataset`(발행 문장이 인용한 **고유 근거** 수를 데이터셋별로 — `datasetId`·`title`·`datalabMenu`(데이터랩 아니면 null)·`count`, 기준 그래프의 데이터셋 전부를 0 포함으로, `datasetId` 순), `shaclPassRate`(아래 검증 기록의 통과 비율, 기록 0건이면 null), `generatedAt`. **미발행(candidate) 문장·근거는 세지 않는다**
  - **검증 기록**: `/v1/sessions/{id}/validate`가 gate-report를 돌려줄 때마다 `{at, sessionId, revision, masterVersion, shapes, passed}` 한 줄을 저장소 옆 `paths.STORE.parent / "validation_log.jsonl"`에 추가(쓰기 실패는 경고만 — 검증 응답을 막지 않는다). 통과율 = passed 수 / 전체 수
  - `GET /v1/stats/graph` → `graphStats`: `masterVersion`, `masterTriples`(기준 그래프 트리플 수), `sessions`(세션 그래프 수), `sessionTriples`(세션 그래프 트리플 합)
  - 라우트 → 질의(`query/`) → 저장소 계층을 지킨다. SPARQL 문자열을 라우트에 쓰지 않는다
