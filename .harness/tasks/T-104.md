# T-104: 파이프라인 CLI(B) — 단계·게이트·실행 기록(`reports/runs/`)
- 레인/워커: L1 / gpt-6-astra        - 선행: T-103 완료(라벨 — develop에 있음)
- 목표(한 문장): 수집 → 행사 → 라벨 → (피처·학습·백테스트 → 일괄 예보)를 한 명령으로 다시 돌리고, 단계마다 06 §8 게이트를 판정해 실패하면 멈추며, 실행마다 계약 `pipeline-run` 기록과 산출물 해시를 남긴다(운영 화면 S8·서식4 재현성 근거).
- 읽을 것: docs/plan/06 §8(게이트 표 — **fetch 신선도 9/25 정정: 오늘 − 40**)·§8 뒤 9/25 메모(labels 게이트), packages/contracts/schemas/pipeline-run.schema.json, services/forecast/src/crowdcast/{data,labels}/(T-101·T-102·T-103 — **호출만**: `visitors`·`events`·`labels`의 CLI/함수), `.harness/backlog.md` 벌크 수집 절(공유 장부 900건), AGENTS.md §3·§5
- 허용 경로: `services/forecast/src/crowdcast/pipeline/`(`stages.py`·`gates.py`·`run_record.py`·`__main__.py` — 파일 하나 = 책임 하나), `services/forecast/tests/pipeline/`
- 실행 산출물(git 제외): `reports/runs/<runId>/run.json`(계약 `pipeline-run`)·`run.md`(사람용 요약), `reports/runs/latest.json`(마지막 실행 id)
- 인터페이스:
  - `python -m crowdcast.pipeline [--from STAGE] [--to STAGE] [--dry] [--max-calls N]` — 단계 순서 = 계약 enum(`fetch`·`labels`·`features`·`train`·`backtest`·`batch`·`publish`). 지금 없는 단계(features·train·backtest·batch — T-203·T-205가 만든다)는 **모듈이 있으면 부르고, 없으면 `skipped` + 이유**(가짜로 통과시키지 않는다). 모듈 경로는 상수 표 하나(`stages.py`)로 — T-203·T-205가 들어오면 표에 이미 적힌 진입점(`crowdcast.models:backtest` 등)을 그대로 찾는다
  - `fetch`: 방문자 벌크 수집(`crowdcast.data.visitors`) — `--max-calls`(기본 0 = 호출 안 함, 캐시만) + 공유 장부 한도 존중, 이어서 `crowdcast.data.events --offline`(TourAPI 호출은 오케스트레이터 몫이라 파이프라인은 하지 않는다). 게이트: `region_daily` 결측률 < 2%(시군구×날짜 격자 기준 — 산식 주석), 최신 관측일 ≥ 오늘 − 40, 장부 한도 이내
  - `labels`: `crowdcast.labels` 실행 → 종료 코드·`labels_g0.json`으로 게이트(부호 검사·골든 제외는 T-103 안에서 이미 판정 — 파이프라인은 결과를 읽어 기록만, 다시 계산하지 않는다)
  - 게이트 실패 = 그 단계 `failed` + 뒤 단계 `pending` 그대로 + 전체 `failed`, 종료 코드 1. `fetch`만 06 §8대로 재시도 1회
  - `--dry`: 실제 쓰기 없이 단계 계획·입력 파일 존재·게이트 입력만 검사하고 기록(`run.json`은 `reports/runs/dry-<runId>/`)
  - 기록: 단계마다 `ms`·게이트(`passed`·`message`)·산출물 `{path, sha256}`(경로는 `data/`·`models/`·`reports/` 기준 상대), `runId` = 시작 시각(KST) + 짧은 난수, `summary`는 한 줄 문장(숫자는 게이트 값 그대로 — LLM 없음). 계약 검증 뒤 쓴다
- 수용 기준(실행 명령):
  - `uv run --package crowdcast-forecast pytest -q services/forecast/tests/pipeline` 통과: 단계 선택(--from/--to), 없는 단계 skipped, 게이트 실패 시 중단·뒤 단계 pending·종료 코드 1, fetch 재시도 1회, 신선도 경계(오늘 − 40 당일 통과·하루 전 실패), 결측률 산식, `--dry`는 산출물 쓰기 0, `run.json` 계약 통과·결정적 해시 기록(합성 입력)
  - 실제 실행: `python -m crowdcast.pipeline --to labels --max-calls 0` → 두 단계 passed(현재 데이터) + `run.json`·`run.md`, `--dry` 완주 — 리포트에 run.json 요약과 해시
- 범위 밖: 피처·학습·백테스트·일괄 예보 구현(T-203·T-205), Dagster 이전(T-108), Ollama 요약(T-106)
- 외부 호출: 기본 없음(`--max-calls`를 주면 data.go.kr — 테스트는 호출 0)
- 코드 규칙: AGENTS.md §5
- **명세 정정(계획 리뷰 — 워커 실행 중 바뀜, 06 §8 fetch 행이 정본)**: 신선도 기준은 오늘 − 40이 아니라 **실제 반영 지연(수집 시각 − 최신 관측일) ≤ 35일**(§3 공개 시점 규칙과 같은 값 — 넘으면 중단). 수집 멈춤 감지: 이번 실행이 수집했으면 최신 관측일이 직전 실행보다 줄지 않음·마지막 수집 성공 시각 기록, `--max-calls 0`이면 "캐시만"으로 표시. TourAPI·특일에는 이 기준을 쓰지 않는다(각각 대상 기간·필요 연도 확보 여부 — 이번 task는 기록만).
