# T-307: 데모 재생 모드 — 저장된 예보팀 trace를 원래 간격으로 SSE 재생
- 레인/워커: L3 / gpt-6-astra        - 선행: T-303 완료(예보팀 런타임·trace 기록 — develop에 있음), T-310 완료(조회 라우트 모양)
- 목표(한 문장): 네트워크·Ollama가 막힌 발표장에서도 `GET /api/team/replay/{traceId}`가 저장된 요청 하나를 **원래 이벤트 간격 그대로** 같은 SSE 계약으로 다시 흘려, 웹이 새 예보와 똑같은 화면을 그리게 한다.
- 읽을 것: packages/contracts/openapi/gateway.yaml(`/api/team/replay/{traceId}`), packages/contracts/sse-events.md(순서 규칙 R1~R11), packages/contracts/rules/sse-sequence.mjs(`sequenceProblems`), services/gateway/src/team/runtime/{events,trace,settings}.ts(지금 trace 한 줄 = `{requestId, event, seq, data}` — **시각이 없다**), services/gateway/src/routes/team-messages.ts(streamSSE 사용법), services/gateway/src/routes/proxy-response.ts(오류 응답 모양 `{code, message}`), docs/plan/02 §5·03 "장애 대비", AGENTS.md §3·§5
- 허용 경로: `services/gateway/src/team/runtime/{events,trace,settings}.ts`(trace 줄에 시각 추가·경로 공유만), `services/gateway/src/team/replay/`(새 폴더: trace 읽기·검증·간격 계산 — 책임별 파일), `services/gateway/src/routes/team-replay.ts`(새 파일), `services/gateway/src/app.ts`(등록 줄만), `services/gateway/tests/`, `services/gateway/fixtures/replay/`(새 폴더: 재생용 trace — 테스트·발표 백업)
- 인터페이스:
  - **trace 기록 보강**: 한 줄 = `{requestId, at, event, seq, data}` — `at`은 이벤트를 **보내기 직전** 시각(ISO 8601 UTC, ms). SSE 봉투(`{event, seq, data}`)는 바꾸지 않는다(계약 그대로 — `at`은 trace 파일에만).
  - **traceId**: `^(s-[0-9]+-[0-9a-f-]{36}|demo-[a-z0-9-]{1,40})$`만 받는다(그 밖은 400 `{code:"BAD_TRACE_ID"}`). `s-…` = 라이브 세션(`settings.traceDirectory` — 경로 상수를 새로 만들지 말고 팀 설정과 **같은 값**을 쓴다), `demo-…` = `services/gateway/fixtures/replay/<id>.jsonl`(커밋되는 발표 백업). 파일 경로는 해석 뒤 해당 폴더 안인지 다시 확인한다. 파일이 없으면 404 `{code:"TRACE_NOT_FOUND"}`.
  - **재생 범위**: 파일의 **첫 번째 requestId** 요청 하나(`done`까지). 한 요청 = SSE 스트림 하나(R2 — `done` 뒤 이벤트 없음). 줄 순서가 아니라 `seq` 순서로 보낸다.
  - **재생 전 검증**(스트림을 열기 전에 전부): 줄마다 JSON·SSE 이벤트 스키마(`sse-event.schema.json` — events.ts가 쓰는 검증기 재사용), 요청 전체를 `sequenceProblems(events, ctx)`에 넣어 위반 0(ctx는 스트림 내용에서: `forecast`가 있거나 게이트 A가 있으면 `new`, 없으면 `followup` + `done.forecastId`), `seq` 0부터 빈틈 없음, 마지막이 `done`. 하나라도 어기면 422 `{code:"TRACE_INVALID", message}`(무엇이 틀렸는지 한 줄) — **깨진 trace를 반쯤 흘리지 않는다**.
  - **간격**: 다음 이벤트까지 대기 = `at` 차이(음수면 0). 한 간격 상한 `REPLAY_MAX_GAP_MS = 8000`(상수 + 주석: 발표 중 LLM 대기 공백을 줄이는 유일한 변형 — 리포트에 명시). `at`이 없는 옛 trace 줄은 앞 이벤트 뒤 `REPLAY_DEFAULT_GAP_MS = 300`. 대기 함수는 주입 가능(테스트는 가짜 시계 — 실제 sleep 금지).
  - **연결 끊김**: 클라이언트가 끊으면 남은 대기·전송을 즉시 멈춘다(타이머 정리). 재생은 trace를 **새로 쓰지 않는다**(재생이 또 다른 trace를 만들면 안 된다).
  - 응답 헤더는 새 예보 스트림과 같게(`text/event-stream`, 캐시 금지).
  - **발표 백업 trace 1개**: `fixtures/replay/demo-yeongjong.jsonl` — `FORECAST_MODE=fake`로 영종 불꽃축제 새 예보를 한 번 돌린 실제 trace(시각 포함)를 복사하고, 사람 이름·연락처 같은 자유 입력이 없는지 확인한다(입력 문장은 계약 예시 문장 그대로). 이 파일로 재생 검증이 통과해야 한다.
- 수용 기준(실행 명령):
  - `npm -w services/gateway test` 통과, 새 테스트: ① **왕복** — 가짜 LLM·가짜 예측으로 실제 세션 한 번 → 생성된 trace로 재생 → 받은 SSE 이벤트의 `event`·`seq`·`data`가 원래 스트림과 **완전히 같음** ② **간격** — `at` 0·120·480ms trace → 대기 120·360 호출, 20초 간격 → 8000, `at` 없음 → 300 ③ traceId 경로 조작(`..`·인코딩된 `%2e%2e`·절대 경로·패턴 밖) 400, 없는 파일 404 ④ 깨진 trace(JSON 오류·스키마 위반·seq 빈틈·`done` 없음·게이트 A 전 `claim`) 422 + 스트림 미개시 ⑤ 여러 요청이 든 파일 → 첫 요청만 ⑥ 연결 끊김 → 남은 이벤트 미전송·타이머 0 ⑦ 재생이 trace 파일을 만들거나 바꾸지 않음 ⑧ 기존 trace 기록 테스트가 `at` 포함으로 통과
