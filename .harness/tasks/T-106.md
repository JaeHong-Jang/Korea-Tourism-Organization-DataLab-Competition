- 인터페이스:
  - **`GET /v1/runs`**: `reports/runs/*/run.json`(기존 `run_record` 목록 함수) 최신순 최대 50개, 계약 배열 검증, 깨진 파일은 건너뛰고 로그(응답은 성공). 절대 경로 노출 없음(기존 규칙).
  - **`GET /v1/ops/freshness`**: 자료별 행 — 방문자(`region_daily` 최신 관측일·마지막 수집 시각·반영 지연 일수, 35일 넘으면 경고 표시), TourAPI(마지막 수집 시각), 기상청(캐시 최신 응답 시각 — 없으면 null), 특일(보유 연도), 일괄 예보(`upcoming` 실행 시각·runId), 사용 모델(`promoted.json` 버전). 계약 스키마 그대로.
  - **실행 요약(`summary.py`)**: 실행 기록에서 사실 목록(단계 결과·게이트 메시지·행 수·모델 버전)을 만들고 Ollama(`OLLAMA_MODEL_FAST`)에 "숫자는 `{{n1}}` 같은 자리표시자로만" 쓰게 한 뒤, **자리표시자 밖 숫자가 있으면 버리고 규칙 문장(템플릿)으로 대체**, 자리표시자를 실제 값으로 채워 `run.json.summary`에 저장(파이프라인 publish 뒤, 실패해도 파이프라인 결과는 바뀌지 않음 — Ollama가 없으면 템플릿 요약). CLI `python -m crowdcast.pipeline summary <runId>`로 기존 실행에도 채울 수 있게.
- 수용 기준: `pytest -q services/forecast/tests`·ruff, 테스트: 실행 목록 정렬·깨진 파일 건너뛰기·경로 비노출, 최신성 지연 계산·경고, 요약 — 자리표시자 밖 숫자 거부 → 템플릿 대체·Ollama 없음 → 템플릿·자리표시자 채움(가짜 Ollama). 실제 서비스 실행·기존 실행 기록 요약 채우기는 오케스트레이터.
